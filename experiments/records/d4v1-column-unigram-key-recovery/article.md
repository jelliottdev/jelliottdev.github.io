# A column solver with a short-key limit

**Result.** The source's column-frequency solver produced 165 complete-page readings using fixed key lengths 2, 3 and 5. None reached the predeclared English score line. The solver recovered **one planted readable passage in 107 of those 165 page-and-key-length settings**; it did not recover the passage in the other 58. Among all LP2 outputs, the highest score was −6.78 on LP2-55 at key length 5, but that setting did not recover the plant. The highest-scoring LP2 output in a setting that recovered the plant was LP2-49 at key length 3 (−6.95). A full-search shuffle comparison found 107 of 199 trials with a maximum at least as high as the overall LP2 best.

![Of 165 page-and-key-length outputs, 107 recovered a planted reading, and none of those passed the English score line.](experiments/records/d4v1-column-unigram-key-recovery/summary.svg)

The [pinned C++ solver](https://github.com/d4v1-sudo/my_cicada_tools_cpp/blob/6bba820aed72184837611a82c79c4587157080aa/src/utils.cpp) asks for a page and a key length. It removes the source's listed possible interrupter positions, divides the remaining runes into repeating-key columns, and chooses the shift in each column that best matches a frequency table from solved pages. Its first preview applies the inferred key to the **original, unfiltered** page. We reproduced that direct numeric preview for fixed lengths 2, 3 and 5 on LP2-00–55, omitting the number-only LP2-50. This is **one source method with three bounds**, not three different cipher ideas.

| Check | Outcome |
| --- | --- |
| Nine archived readings encrypted with fixed repeating keys | Exact key recovered on 9/9 at length 2, 9/9 at length 3, and 8/9 at length 5 |
| The same readable passage fitted to each target page's length, with its exact source interrupter positions | 107/165 key recoveries; every planted passage also clears the English score line |
| LP2 complete-page outputs | 0/165 clear the −5.5 English score line, including 0/107 in settings that recovered the plant |
| 199 shuffled-page trials, each rerunning all pages and all three lengths | 107 global maxima equal or exceed the strongest actual output; plus-one tail 108/200 |

This check used **one constructed passage**, adjusted to each target page's length. Recovering it shows that a setting can work on that passage; failing to recover it leaves that setting without this positive check. It is not a statistical power estimate or a guarantee for other English text. The source removes listed rune positions **before finding the key**, which can change column phase, but decrypts the unfiltered page afterward. On the 23 pages where listed positions fall inside the page, many plants fail for that reason. A different key schedule or an implementation that preserves phase after removals is outside this replay. The source's automatic key-length setting also chose a longer period rather than the planted length 3 for all nine complete known-reading controls, so this record makes no negative claim about automatic mode.

The English quadgram score and its −5.5 line are **our added screen**, calibrated against the nine complete readings and 199 complete-search shuffle controls. The original program derives its unigram target from known solved readings; checks on those readings are in-sample for that key-inference target, not an independent language-generalization test. Its unigram fitness alone does not certify English. We did not count its alternate rune, Latin or patched-key transforms as tested here. The [source-order correction note](experiments/records/d4v1-column-unigram-key-recovery/execution-note.json) documents a discarded exploratory implementation whose floating-point summation could change a tied shift. The final key inference agrees with compiled original C++ on nine fixed page-and-length cases, and an independent checker reconstructs every target row, plant and shuffle.

## Reproduce

The [frozen plan](experiments/records/d4v1-column-unigram-key-recovery/plan.json), [complete results](experiments/records/d4v1-column-unigram-key-recovery/results.json), [source interrupter map](experiments/records/d4v1-column-unigram-key-recovery/interrupt-map.json) and [source target frequencies](experiments/records/d4v1-column-unigram-key-recovery/source-target.json) are supplied with the experiment. From the repository root run `python experiments/records/d4v1-column-unigram-key-recovery/run.py --check`, followed by `check.py` and `plot.py --check`. The checks require Python with NumPy and Numba, but no network fetch or upstream source checkout. The unlicensed source program is linked and pinned by revision rather than copied into the archive.
