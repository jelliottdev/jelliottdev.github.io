# Do fixed local rules preserve too many repeats?

A fixed rule that treats the same input unit the same way tends to preserve repeats. Wulfic's Stages AA and Z turn that idea into two precise tests on the unsolved LP2 text. **The controlled tests exclude the simplest short-context and short-block versions. Longer contexts and blocks usually cannot be distinguished from the controls.** This is a limit on those models, not a reading of the manuscript.

![Controlled repeat tests for local context widths, repeated words and aligned blocks](experiments/records/wulfic-local-codebook-invariants/comparison.svg)

## What was tested

**Stage AA: local context.** Suppose each output rune comes from a fixed, position-independent rule applied to nearby plaintext runes. If the same input window appears twice, the resulting output window must repeat. The source checks context widths 0–12, output groups of 3–7 runes, and two scopes: compare only inside each manuscript section or join the nine sections. It first measures the repeated output groups, then asks whether a proposed width would have produced more of them.

**Stage Z: fixed codebooks.** A fixed word table gives the same ciphertext to every copy of a word. A fixed, invertible block table likewise gives the same output to every copy of an aligned block. The source checks repeated words of at least two runes and aligned blocks 2–8 runes long at every starting offset. Each block length is tested both within sections and across the joined text. This covers **72 declared cells**: two word comparisons and 70 block comparisons.

These are structural tests. They do not look for English words or choose a key after seeing a promising passage. The source also lets its simulated encoder redraw 81% of adjacent repeat collisions, a measured LP2 feature. That matters: a simple fixed-codebook test without the collision rule would be easier to reject and less relevant.

## Result

| Source test | Excluded by its controls | Not resolved |
| --- | ---: | ---: |
| AA context-width cells | 5 of 26 | 21 of 26 |
| Z repeated-word cells | 2 of 2 | 0 |
| Z aligned-block cells | 24 of 70 | 46 of 70 |

The AA exclusions are widths **0–2 within sections** and **0–1 in the joined stream**. Every other declared width lacks enough control power for an exclusion. In Z, the two word-codebook comparisons are excluded. All cells for blocks of 2–4 runes are excluded. Six of ten five-rune cells are excluded; the remaining four and every cell for lengths 6–8 are unresolved. **Unresolved does not mean compatible:** there are too few preserved repeats in the positive examples to separate those cases reliably from random text.

For each cell, the source generated 1,000 flat-rune null samples and 200 positive samples from each of two sources: Emerson prose and decoded LP1. It applies the same collision rule to the positive samples. An exclusion requires both positive sources to separate cleanly from the null and the LP2 count to lie below both positive lower bounds. The [exact result tables](experiments/records/wulfic-local-codebook-invariants/source-stage_z_results.tsv) show every cell; the [compact summary](experiments/records/wulfic-local-codebook-invariants/results.json) groups the verdicts. No LP2 repeat statistic is reported as a positive cipher identification.

## How to read the finding

Equal plaintext need not give equal ciphertext if the rule also depends on position, a running key, previous ciphertext, a changing alphabet, or some other state. Such a cipher is outside these fixed local-codebook tests. Different word boundaries or a corrected transcription would also change the measured repeats. Stage AA's 21 unresolved cells and Stage Z's 46 unresolved cells should remain open until a stronger control or another invariant makes them testable.

The supplied anti-doublet model is a control, not a demonstrated account of how LP2 was made. The controls check whether this particular repeat test can reject its proposed construction. They do not establish that the construction is the only way to create the manuscript's low repeat rate.

## Reproduce

The bundled AA and Z tables were regenerated by executing the [pinned Stage AA](https://github.com/Wulfic/Cicada3301-Liber_Primus/blob/bf89d3d13aad2b8f2c95ab195cf1b092f250775c/tools/run_stage_aa.py) and [Stage Z](https://github.com/Wulfic/Cicada3301-Liber_Primus/blob/bf89d3d13aad2b8f2c95ab195cf1b092f250775c/tools/run_stage_z.py) programs at commit `bf89d3d`, with the source's complete grids, seeds and controls. Every output table was compared byte-for-byte with the pinned repository. The source repository and its code are linked rather than copied into this ZIP.

From the extracted Liberpedia repository, Python's standard library is enough to verify the bundled results and independently recount every LP2 word, sliding group and aligned block:

```text
python experiments/records/wulfic-local-codebook-invariants/run.py --check
python experiments/records/wulfic-local-codebook-invariants/check.py
python experiments/records/wulfic-local-codebook-invariants/plot.py --check
```

The [plan](experiments/records/wulfic-local-codebook-invariants/plan.json) pins input hashes and the exact grids. The optional `replay_source.py` script runs both upstream programs from a checkout at the recorded commit, or compares completed rerun tables with `--verify-output-dir`; a full source rerun requires that repository and its dependencies. The independent checker reads Liberpedia's page text afresh and checks the manuscript counts against the source tables. It also checks a small planted example in which a fixed one-to-one relabelling must preserve word and block repeats.
