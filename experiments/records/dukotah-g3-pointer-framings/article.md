# Base32 and coordinate pointer checks

**Result:** The source's only workable pointer flag did not fire. Its longest repeated-symbol run was **16** characters for prime values, **10** for prime indices and **16** for totients. The largest of 200 shuffled controls reached **22, 15 and 22** respectively. A 32-symbol planted run *did* fire, so this test can detect that kind of conspicuous repetition.

![Observed repeated-symbol run beside the maximum of 200 shuffled controls for each number stream.](experiments/records/dukotah-g3-pointer-framings/lowentropy.svg)

The [pinned G3 program](https://github.com/Dukotah/cicada3301/blob/f08b20b632d91209ddbaa747e8e2f23df0c78ba1/liber-primus/analysis/round22/B-turtle-spatial-render/g3_coord_decode.py) takes the 12,956 runes of 55 nonempty LP2 pages, including F, and reads each rune as its prime value, one-based prime index or prime totient. It maps each value modulo 32 to a base32 character and also concatenates its decimal digits. We reproduced all **15 measured values** and **3,000 source null calls** (three streams × five measurements × 200 seeded shuffles) against the [source's saved output](https://github.com/Dukotah/cicada3301/blob/f08b20b632d91209ddbaa747e8e2f23df0c78ba1/liber-primus/analysis/round22/B-turtle-spatial-render/g3_results.json). The source and this site's page transcriptions give the same rune sequence, one rune at a time.

The other reported counts do not test what their labels suggest. **Every** character produced by the modulo-32 mapping is in the base32 alphabet. A 12,956-character stream therefore contains exactly floor(12,956 ÷ 16) = **809** nonoverlapping 16-character matches and floor(12,956 ÷ 56) = **231** 56-character matches, whatever the rune order. These matches do not validate an onion address. The decimal string contains only digits, while the latitude/longitude pattern requires a decimal point and a separator; its count must be zero. The program also reports the fraction of plausible integer coordinate pairs, but that quantity never enters its pointer-flag decision.

The [source preregistration](https://github.com/Dukotah/cicada3301/blob/f08b20b632d91209ddbaa747e8e2f23df0c78ba1/liber-primus/analysis/round22/B-turtle-spatial-render/PREREG.md) describes additional mod-M and ASCII-coordinate readings. Those are not executed in `g3_coord_decode.py`. This replay therefore says **no unusually long repeated-symbol run under the implemented mapping and shuffle control**. It does not exclude other coordinate encodings, valid onion addresses, or a sparse pointer built with another rule. The earlier [turtle-path replay](#/experiments/lp2-turtle-spatial-replay) covers the separate drawing test from the same source lane.

The saved [plan](experiments/records/dukotah-g3-pointer-framings/plan.json) records the exact source revision, inputs, seed schedule and controls. The source's target results were already visible before our plan was written, so this is a **retrospective replay**, not a newly preregistered discovery. Run `python experiments/records/dukotah-g3-pointer-framings/run.py --check --check-site` and `python experiments/records/dukotah-g3-pointer-framings/check.py` from the repository root to verify the source output and an independent detector implementation. The bundled `input-indices.bin` and `source-results.json` let the same checks run offline; `--check-site` additionally compares all 55 current page records.
