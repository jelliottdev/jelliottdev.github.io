Hypothetically changing all **450 O/A/AE rune readings** disputed by one source reader to that reader’s suggested alternatives raises adjacent repeats from **86 (0.664%) to 103 (0.795%)**. A German-corpus comparison floor used in this source analysis would require **126**; it is not a universal language threshold. The 450 suggestions have **not** been established as 450 mistakes. These counts use adjacent rune pairs in the joined stored stream, including line and page joins.

![Three adjacent-repeat counts: stored text 86, all 450 alternatives 103, and the source comparison floor 126.](experiments/records/rune-reading-sensitivity-t3/comparison.svg)

The same substitutions move the normalized index of coincidence from **0.999874 to 1.013823**. That is a substantial change to a different statistic, so the result is not “transcription does not matter.” In the source’s 400-trial targeted grids, the located alternatives and the broader O/A/AE family give different repeat counts. A family-wide random change is not the same experiment as replacing the 450 located readings. [See the saved grid](experiments/records/rune-reading-sensitivity-t3/out_targeted.json).

The reader behind those alternatives matched its own canonical labels on **13,088 of 13,136** corpus runes and returned **180/180** on the solved-page control. Its 450 disagreements were also adjudicated using the same source pipeline. The pipeline builds a global label alignment using canonical text from *all* pages, including the pages later treated as controls. Excluding a page’s direct votes afterward does not make that test independently held out. These figures describe **agreement with the source transcription**, not a measured error rate for the original images. The separate [stored correction check](#/experiments/transcription-correction-sensitivity) concerns seven documented LP2 notation edits; it did not test these 450 hypothetical substitutions.

The source also tests a different question: can its known-key, key-skip decoder recover a planted passage after *uniformly random ciphertext substitutions*? In fresh source runs, median recovery first drops below 90% at a book-equivalent **1,800 changes** for 120-rune LP1 passages and **900** for 400-rune LP1 passages. At 450 equivalent changes, the medians are **96.7%** and **96.4%**. [Inspect the 120-rune](experiments/records/rune-reading-sensitivity-t3/out_decode_L120_LP1.json) and [400-rune](experiments/records/rune-reading-sensitivity-t3/out_decode_L400_LP1.json) results.

An exact-hash KJV input recovered from a separate source capsule also let us replay the source’s **12,956-rune, six-replicate full-book fixture**. Its six declared error levels match the saved source results. At 450 substitutions, median known-key recovery is **86.2%**, though the correct-key scores still separate from wrong-key scores; at 900, median recovery is **19.9%** and the score distributions overlap. [Inspect the full-book fixture](experiments/records/rune-reading-sensitivity-t3/out_decode_L12956_KJV.json). The short fixtures use LP1 text while the full-book fixture uses KJV text, so their difference cannot be attributed to length alone. Six replicates do not measure broad decoder sensitivity. None of these fixtures tests errors specifically at the 450 O/A/AE locations or establishes that an actual LP2 key would fail. The source output’s inner `conditionals.register` label is hardcoded `LP1_REAL`; the run command and top-level `register` correctly identify this fixture as KJV.

## What was run

The pinned 12,956-rune stream passed all 13 source baseline checks. All 450 source alternatives mapped to distinct matching positions. The source’s planted doublet control and 20-case beam parity gate passed. We then reran the complete declared random, dense and O/A/AE **400-trial grids**, the 14 error levels for each LP1 decoder fixture (120 replicates at 120 runes; 60 at 400 runes), and the source’s separate six-level KJV full-book fixture (six replicates per level). Fresh aggregates match the pinned source numerically; runtime fields and insignificant floating-order differences vary. A separate checker recounts adjacent repeats and IoC directly from the [stored rune/alternative snapshot](experiments/records/rune-reading-sensitivity-t3/input-snapshot.json).

Run `python experiments/records/rune-reading-sensitivity-t3/run.py --check` to verify the inputs, source archive and saved results; `python experiments/records/rune-reading-sensitivity-t3/check_fullbook.py` independently compares the archived and fresh KJV rows. Add `--replay` to rerun the source grids from the [MIT-licensed source snapshot](experiments/records/rune-reading-sensitivity-t3/source-snapshot.zip); `--jobs 3` runs independent full-book error levels in isolated source trees and merges them in their original order. The exact KJV bytes come from the separately hosted [pinned source corpus](experiments/records/dukotah-offset-model-integrity/source-kjv.txt) and are hash-checked before use. Replay takes several minutes and needs NumPy and SciPy for the source image-pipeline module. The ordinary checks use only Python’s standard library.

The six-level full-book replay was added after the earlier LP1 work when the pinned KJV bytes became available. Its [separate frozen plan](experiments/records/rune-reading-sensitivity-t3/fullbook-plan.json) records that timing and the exact source settings. We did not regenerate the historical 62-entry dependency graph. The result does not verify the manuscript transcription or close other possible error patterns, cipher models or language registers.
