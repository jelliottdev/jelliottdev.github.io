# Do fixed affine rune maps produce literal web markers?

One map produces one literal **HTTPS** window: LP2-36, rune start 226 using zero-based positions, under `P=(24C+28) mod 29`. **HTTP** is the prefix of that same window. WWW and ONION have no matches. These are literal marker counts, not recovered URLs: punctuation and hostname grammar were not tested.

The frozen readout covers all 812 invertible GP29 affine maps at every fitting rune position in original LP2-00 through 55. Fifty-five pages contain 12,956 runes; LP2-50 has none. Every non-rune separator is removed, headings retain their original order, and searches never cross page boundaries. One ASCII letter uses its canonical one-letter GP rune. A digraph-labelled rune is one separate rune slot, not two searchable letters. No alternative spellings or marker variants were added after counting.

The sole cipher window has indices `4,14,14,3,20`, whose GP labels are `R X X O L`. The map sends it to `8,16,16,13,15`, or `H T T P S`. The saved snippet is `W H IA TH Y M B A [HTTPS] EO M F X U EO A`; spaces here delimit rune slots, and brackets mark the tested token. They do not recover original word spacing or punctuation. The HTTP and HTTPS rows share one page, key and start and therefore are not independent candidate locations. Both rows, exact source line/column positions and their bounded snippets are retained in `matches.json`.

WWW has a stronger pattern constraint. Every static bijective substitution preserves symbol equality: three decoded W runes require three identical adjacent ciphertext runes. The original page streams contain **zero equal-symbol triples**, even after separators are removed. Literal WWW is therefore incompatible with any static bijective rune substitution in these page streams, including every affine map. This does not exclude web addresses without WWW or a cipher whose symbol map changes by position. ONION's absence is established only for the declared affine maps.

All 3,248 planted map/token cases recover their fixed-offset markers: each of 812 maps enciphers synthetic contexts containing each of the four tokens, and the scanner recovers the marker at rune offset 8. A separate implementation translates every complete page into a one-codepoint-per-rune decoded stream and performs overlapping substring searches. Its 45,472 page/map streams, including 812 empty-page streams, reproduce every match tuple, index window, source location and snippet. It independently repeats all 3,248 synthetic controls and checks the equal-triple invariant.

This is one grouped marker-readout follow-up to the existing whole-page affine GP29 English-score record. It reuses the same 812-map keyspace for a different fixed output predicate. The earlier nine opening-crib capacity checks do not supply an all-position marker census. This record makes no p-value, language-score or URL claim; other key layers, transpositions, alphabets and spellings remain untested.

Run `python experiments/records/url-marker-affine-census/run.py`, then `python experiments/records/url-marker-affine-census/check.py`. The plan pins `data/index.json` and all 56 original page files before target counting. Both scripts verify those hashes and use only the Python standard library.
