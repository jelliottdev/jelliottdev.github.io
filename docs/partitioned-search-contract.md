# Complete searches across bounded jobs

This is an implementation contract, not a claim that composite searches are
available to visitors. Existing finite searches and saved results remain valid.

## One question, complete declared scope

The public question retains its aim, ordered method, evaluation rule, input
edition, alphabet and exact pages. A maintained pinned bank defines the complete
set of key settings. Internal ranges divide execution work; they are not new
ideas, experiment pages or user choices.

The parent identity binds that complete declaration and its source pins. Each
job binds the parent identity and its exact range. Changing a source, page,
method, evaluation or key bank creates a different parent. Merely changing
scheduling must not change the scientific question.

## Current foundations

- `pinned-domain-partitions.js` and its Python counterpart plan complete,
  disjoint ranges under the existing program and page-case limits. Planning
  neither admits tasks nor proves that controls fit or pass.
- The maintained bank contains every vector from both historical rotating
  schedules, including the 648 vectors with 324-rune periods. Bank membership
  does not bypass the repeating-key engine's 256-value limit.
- `periodic-key-scope.js` can represent a complete periodic cycle as a finite
  stream for an exact pinned input scope. It retains whole cycles and their
  unused tails, checks the existing finite-stream bound, and binds every input
  page and reset rule. This is a scope-bound representation proof, not global
  equivalence, task admission or an experiment result.
- `pinned-domain-members.js` binds the full input scope before compiling a
  selected setting and page subset through the existing canonical compiler.
  Private parent and member tokens protect that binding. Compilation does not
  authorize execution or claim that a control passed.
- `scripts/pinned_domain_controls.py` creates full Warning controls with the
  independent Python inverse encoder and commits each synthetic task and result
  hash offline. `pinned-warning-controls.js` reconstructs one selected control,
  checks its committed task hash, then checks the complete 184-rune output and
  committed result hash. It never invents an expected result with the decoder.
- `pinned-domain-case-ledger.js` requires an internal persistent-source
  authority, independently verifies the original computation, and unions global
  setting/page coverage with compact bitsets. Hashed, paged snapshots restore by
  reloading and re-verifying sources. Its authority interface is not yet wired
  to a public endpoint. `pinned-domain-source-authority.mjs` now reads actual
  public-associated saved receipts, checks original identities and arithmetic,
  and issues private certificates. Cross-idea reuse requires the same exact
  computation, rather than matching a filing label.

## Maintained sources and admission

`build_pinned_domains.py` retains both complete 2,561-setting rotating banks
and their 5,122 independently encoded full-Warning commitments. The server
registry pins the exact manifest bytes; a visitor cannot provide replacement
source metadata or control expectations. Generated assets alone authorize
neither a run nor a scientific conclusion.

The admission bridge derives the selected member from that maintained source.
Its immutable prepared-plan basis records the complete parent, selected pages,
member and independent control identities. The existing task gate rechecks the
basis on creation and on an idempotent relink. Actual result admission still
replays the original bounded task. This is the server/database admission link;
a public coordinator, durable aggregate coverage and browser continuation remain
required before enabling these searches.

## Required before enabling execution

1. The server derives each child from the immutable parent declaration. It
   must not accept a browser-supplied replacement child list or altered card.
2. Admission binds parent revision, child range, actual compiled domain,
   selected settings, program, official inputs and task identity. Existing
   finite-member checks still validate the bounded executable task.
3. Full independent known-answer controls remain mandatory. A future lazy
   control format must commit to independently generated task and result
   hashes. Expected results cannot be generated by the decoder being tested.
   A control template's presence does not mean every member has passed.
4. Aggregate progress comes from verified unique program-and-page case
   identities. Never add advertised job totals or count duplicate receipts
   twice. If distinct named settings compile to the same computation, retain
   their alias relationship explicitly rather than inventing extra evidence.
5. A negative result requires complete verified coverage and completed evidence
   lookups across the entire parent domain. Finishing a job is not finishing
   the search; finding an opening does not establish a decryption.
6. Pause, resume, retries, service limits, stale source recovery and cancellation
   preserve saved work and the same parent identity. A reload rechecks verified
   evidence before selecting the next missing work.
7. Visitors see one question, one saved-work count and one run/resume action.
   Internal ranges remain invisible. Unsaved local results remain separate
   from saved verified progress.

Enable the composite flow only after these gates pass through the real browser,
server and database loop, including overlaps, source changes and interruption.

## Bounded recovery and scheduling

Ledger snapshots can now be restored a bounded number of receipts at a time.
The private restoration token pins the complete parent, snapshot manifest, page
digest and receipt offset. A failed lookup retains the verified prefix; a retry
continues at the same receipt. Partial restoration never exposes a normal ledger
or a completed-search verdict. Finalization requires every committed reference.
These continuations are process-local, not durable browser resume tokens.

The persistent authority can resolve a private certificate in one database read.
Recovery still checks arithmetic in both the persistent authority and the ledger;
it avoids a duplicate database lookup, not an independent verification gate.

`pinned-domain-next-work.js` selects missing coordinates directly from the
verified bitsets. It retains the same full parent and offers bounded jobs without
deriving every program. Suggestions neither reserve work nor authorize execution.
Reaching the end of a scheduling range cannot hide missing earlier coordinates.

## Remaining coordinator constraint

`pinned-domain-coverage-store.mjs` and migration 0019 provide the private durable
journal. Trusted maintained-source loaders bind the full parent, manifest,
verifier version and evidence epoch. Ingestion accepts at most twelve exact saved
receipt references, checks their public database association and arithmetic, and
stages the entire bounded batch before four atomic bulk statements. Unique
setting/page facts and program/page facts prevent retries or overlaps from
inflating either count. Reopening reads the committed counts without replaying
all historical output. These are trusted server-maintained counters, not a
portable proof that a browser may supply or alter.

New saved receipts preserve that generation. Updating or removing earlier
evidence invalidates it; the old rows remain for audit and the new generation
requires bounded re-ingestion. Read and write fences reject mixed generations
or concurrent revisions. Completing case coverage always remains explicitly
lookup-pending: this layer has no operation that can declare discovery finished
or issue a negative scientific verdict. The schema is not yet activated by a
public coordinator.
Ingestion budgets cover both receipt bytes and database query counts. Bound
parameters and batch statements still count against platform limits; one INSERT
per case is not a scalable bulk write. Keep staged source/case inserts compact
and transactional, and test query counts against the conservative Free-plan
budget in the [D1 limits](https://developers.cloudflare.com/d1/platform/limits/).

The public coordinator must still join maintained-source admission, durable
coverage, bounded discovery of existing evidence, and browser pause/resume.
Complete case coverage is not a negative conclusion while evidence discovery is
unfinished. Do not expose an unbounded restore endpoint or claim an in-memory
ledger or private recovery token supplies durable aggregate progress.

## Public handoff to consolidate

Variation creation currently saves a child question and calculation, then links
to a task workspace. The visitor encounters Create check, Open check, Run in
browser, and Save and update question as separate transitions. A reviewed run
intent exists in the ordinary question flow; the variation link deliberately
does not imply one. Preserve that consent boundary when consolidating the flow.

The coordinator should return to the persistent question after review, with one
clear Run/Resume action and visible remaining scope. A creation link must not
silently start work. Saving an idea, running a calculation, saving its result and
supporting a scientific conclusion remain separate operations even when their
product presentation is simpler.
