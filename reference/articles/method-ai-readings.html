AI-assisted candidate interpretation

Treat generated readings as proposals requiring independent, reproducible checks.

A language model can suggest interpretations, candidate keys or code, but a fluent answer is not a recovered plaintext. A useful result must expose an independently executable rule connecting the original input to its output.

Major variants

Direct translation prompts, image interpretation, key suggestions, script generation and ranking existing candidates are different tasks. Each needs its own success criterion. A program produced with AI assistance can be checked independently; a persuasive explanation alone cannot establish a decoding.

What a test must specify

Record model version, prompt, input representation, settings, number of attempts and selection procedure. Separate tools that perform arithmetic from model-generated explanations. Retain unsuccessful responses when assessing reliability.

If no rule connects the original symbols to the sentence, the result is a hypothesis to investigate, not a decoding to reproduce. Keep it distinct from a program that computes a specified transformation. See crib testing and evaluating candidate readings.

Trace the output back to the input

For a symbol-by-symbol method, request the source position, input value, key or state, operation and output for each step. A block or transposition method needs its corresponding block or position trace. Check the first few steps by hand and replay the whole method independently. Any skipped symbol, altered spelling, inserted word or exception belongs in the trace.

Inspect whether the program reads the declared input at all. A script can return a stored expected phrase, use a hidden lookup, or calculate a different operation from the explanation. Change a controlled test input and verify that its behavior follows the declared rule. A script's successful exit status and a fluent printed message are not sufficient checks.

Deriving an unrestricted additive key from a desired sentence also guarantees a fit. Asking a model to produce that key does not create independent support for the sentence. Require the key restrictions and test them, as described in unrestricted keys and constraint models.

Use tests that answer distinct questions

A published solved passage is useful for checking whether the supplied code reproduces its documented solution. It is weaker as a test of independent discovery: the answer might already be available to the model through prior material or the supplied context. Do not infer discovery from a correct answer alone.

For a recovery test, prepare new synthetic fixtures with a fixed algorithm and withheld keys or plaintexts. Include both recoverable cases inside the declared search and cases outside it. Keep evaluation answers out of prompts, filenames, comments and tool outputs available during the attempt. The person or process checking the result can retain them separately.

For a false-reading test, supply controls that lack the proposed structure under a stated null model. Decide beforehand whether success means exact symbol recovery, a correct key, a bounded ranking score or a justified abstention. A method that returns plausible prose for every input has not demonstrated exact recovery.

These tests measure behavior on their particular fixtures. Synthetic success does not establish that the manuscript uses the same cipher, and a failure on an out-of-scope cipher does not disprove recovery within scope. See null models and candidate scoring.

Count the selection process

Keep the full set of attempted prompts, candidate readings, follow-up corrections and model-produced programs. If the best of twenty responses is selected, compare it with controls allowed the same twenty attempts and selection rule. Changing the prompt after reading evaluation answers turns those examples into development material.

Separate conversational reproducibility from computational reproducibility. Preserve the exact response that proposed the rule. Then preserve a deterministic implementation, inputs and outputs so others can check that rule without needing the model to produce the same wording again. If a model remains part of the scoring pipeline, its calls and configuration are part of the experiment and need their own documented evaluation.

How to evaluate a result

Use blinded known-answer and shuffled-input controls with objective scoring. Verify proposed transformations with independent code and untouched text. A model should not receive the answer while being evaluated on whether it can recover it.
