The LP2-56 hash target

The exact printed value, its representation, and the assumptions a candidate check must state.

LP2-56 has a known reading titled “An End.” Its text refers to a page in the deep web that hashes to the hexadecimal value printed between the runic passages. Decoding the surrounding runes and finding the referenced page are separate tasks.

The page record separates the printed hexadecimal block from the runic passages and red punctuation. Five large black dots sit below the text; the illustrated dot guide records them independently of the hash.
The literal target
The archived transcription preserves five printed rows:
36367763ab73783c7af284446c
59466b4cd653239a311cb7116
d4618dee09a8425893dc7500b
464fdaf1672d7bef5e891c6e227
4568926a49fb4f45132c2a8b4
Concatenating the rows yields 128 hexadecimal characters, representing 64 bytes, or 512 bits. The rows are presentation breaks; preserving them in a text file is different from the single digest string used for comparison.

Length is evidence of format, not proof of an algorithm
A SHA-512 digest has this length. The quoted decoded instruction does not name SHA-512 or define which bytes of a “page” should be hashed. Length alone cannot distinguish all algorithms that produce 512-bit outputs. State SHA-512 explicitly as an assumption when testing a candidate.
A URL string, an HTTP response body, an HTML source file, rendered text, and a screenshot are different inputs. Their hashes need not agree. Encoding, line endings, compression handling, and trailing newlines also matter. Do not silently normalize a candidate after a mismatch.

Extract the target from the shipped reading
import json, re
from pathlib import Path
page = json.loads(Path("data/pages/lp2-56.json").read_text(encoding="utf-8"))
lines = [line.rstrip("/") for line in page["reading"]["literal"].splitlines()]
rows = [line for line in lines if re.fullmatch(r"[0-9a-f]+", line)]
target = "".join(rows)
assert len(rows) == 5 and len(target) == 128
assert len(bytes.fromhex(target)) == 64
print(target)
This extracts a preserved target. It does not discover a destination, query a network, or test candidate pages. Use the reading recipe to reproduce the surrounding text independently.

Compare a local candidate file
The candidate-file checker makes one explicit assumption: SHA-512 is the algorithm to test. It reads an existing local file as bytes, without parsing HTML, decoding text, changing line endings, or making a network request.
Extract the reference-data bundle and run from that folder, replacing the quoted path with the file you want to check:
python scripts/check_lp2_target.py "candidate.html"
The JSON report includes the file’s byte count, SHA-256 for identifying the tested bytes, computed SHA-512, preserved target digest, and matches. It also records the hash of the page record from which the target was extracted. The script reads the candidate and prints the report; it does not modify either source file.
	Exit status	Meaning
	0	The computed SHA-512 equals the target.
	1	The exact tested bytes do not match under SHA-512.
	2	The input could not be read or the target record was invalid; no comparison result was produced.
An exit status of 1 is an ordinary mismatch, not a script malfunction. A report identifies what was hashed, but cannot supply missing provenance: record where the candidate came from, when it was obtained, and how it was saved. A browser’s saved HTML and a captured response body may contain different bytes even when they display similarly.
Record exactly what a candidate check establishes
A mismatch excludes the tested bytes under the chosen algorithm. It does not exclude every version of a site, every serialization, or every algorithm. A reported match should include the exact candidate bytes, their provenance, the hashing operation, and an independently repeatable comparison. See checksums and reproducibility.

A hash comparison is not a location
Read hashes, addresses and retrieving the target for the difference between checking a known file and locating unknown content. It explains why moving identical bytes need not change their digest, why Tor’s protocol chronology does not identify this target, and why a complete GNUnet CHK needs more information than one printed hash.
