Checking and comparing transcriptions

Compare exact files and rune streams, locate disagreements, and document image-backed corrections before rerunning experiments.

A transcription is a reading of an image. Before testing a cipher, establish which transcription your script uses and how it differs from other versions. Matching file hashes prove that the bytes agree; matching rune streams prove that the selected symbols agree. Neither check proves that the symbols were copied correctly from the manuscript.

Three checks, three different questions

	Check	What it establishes	What can still differ
	Exact file bytes	The two files are identical	Both can contain the same copying error
	Ordered rune stream	The recognized runes match in sequence	Punctuation, digits, spaces, line endings and other text
	Image review	A reviewer checked specified marks against a specified image	Unreviewed regions and ambiguous marks

Several repositories may descend from the same source. Agreement among them is then useful for tracking copies, but is not several independent visual checks. Likewise, decoding a solved page into recognizable language can help diagnose a mistake without proving every copied rune or separator correct. Preserve the original evidence when proposing a correction.

Compare two files

Extract the reference-data bundle, keeping its scripts and data folders together. Put the two UTF-8 text files you want to compare in that folder. Run:

python scripts/compare_transcriptions.py old.txt new.txt

Use py or python3 if that is your Python command; see running the scripts. The tool reads both inputs without changing them. It prints JSON containing their SHA-256 hashes, byte and rune counts, non-rune character counts, exact-text changes and rune-only changes. JSON escapes such as \u16a0 represent Unicode characters; they keep the report readable by programs even when a terminal cannot print runes.

For a quick installation check, compare one archived file with itself:

python scripts/compare_transcriptions.py text/lp2-00.txt text/lp2-00.txt

Expect bytes_equal: true, runes_equal: true, and empty change lists. This checks the comparison command, not the accuracy of LP2-00. Run its small regression suite with python scripts/test_compare_transcriptions.py. You can also download the script; it requires the alphabet in data/index.json.

Read a disagreement

Consider two invented examples. They demonstrate the output conventions and are not corrections to a manuscript page.

	Left	Right	Interpretation
	ᚠ-ᚢ	ᚠ ᚢ	Exact text differs; rune streams agree. The delimiter change still matters to word-based analyses.
	ᚠ-ᚢ	ᚠ-ᚦ	Second rune differs. The rune range is [1, 2); the source character offset is 2.

Ranges begin at zero and exclude the end position: [1, 2] in the report selects the second rune only. Source offsets count Unicode code points in the exact decoded file, not UTF-8 bytes. File line and column numbers begin at one. An LF newline starts a new file line; the archive's / line-boundary marker does not. Use the transcription conventions to distinguish physical file lines from manuscript rows.

An insertion has an empty left range; a deletion has an empty right range. The nonempty side supplies the positions of the affected symbols. Repeated runs can admit several plausible alignments, so a reported position is a place to inspect, not a unique reconstruction of how the error happened. The tool uses SequenceMatcher with its automatic frequent-symbol suppression disabled, so a small alphabet is not treated as ignorable background.

What the rune-only view leaves out

The tool selects the 29 symbols in the bundled alphabet. It rejects unfamiliar characters in the Unicode Runic block rather than dropping them silently. Other characters remain visible in the exact-text changes and non-rune counts. A Latin transliteration therefore has zero recognized runes: two empty rune streams can compare equal without providing any rune transcription evidence. Always inspect the counts and input type.

No Unicode normalization, spelling repair, punctuation substitution or newline conversion is applied. A byte-order mark and CRLF versus LF line endings consequently remain visible in the exact comparison. That is deliberate: readers can decide which differences matter to a particular experiment, instead of having the script erase the decision.

For a concrete case, see LP2-18’s reported 17-rune word: removing a clause boundary joins two tokens into a candidate with sum 987. The rune-only stream stays the same, but the claimed word changes.

Review the image and record a correction

Identify the release and page, archived text hash and original JPEG hash. Use the page record's downloads rather than a thumbnail or compressed screenshot.
Locate the disputed mark using the text offset and its neighboring runes. Record the manuscript row and a rectangle in original-image pixels.
Show the old symbol and proposed replacement alongside the image detail. Keep uncertain readings as alternatives; a confident-looking AI transcription is not additional source evidence.
Store the reviewed version separately from the archived input. Include the date, rationale and review scope so others can repeat the check.
Rerun affected controls and experiments on both versions. Report which counts, alignments or outputs change, including results that remain unchanged.

A substituted rune can change frequency counts and prime sums. An inserted or deleted rune can also shift all later key positions in a continuous cipher. A delimiter-only correction may leave whole-page IoC unchanged while changing word lengths or a word-reset cipher. The effect depends on the experiment's declared input rules.

This guide and tool provide a comparison workflow, not a claim that every page has been manually reverified. Consult the individual page's archived and reviewed views for existing visual-review records. Related: file integrity · image coordinates · documenting an experiment.


Which pages have a reviewed text layer?

The current published records contain eight separate reviewed-text layers. Seven change only non-rune characters; one changes the rune sequence. The other 67 records do not contain a separate reviewed layer. These are counts of published data layers, not counts of pages certified as correct or incorrect.

	Page	Recorded change	Effect to check

	LP1-10	Exchange the archived I/E order at zero-based rune positions 116–117; the reviewed word is BELIEUE.	Order-dependent operations change. The two-rune sum and whole-page frequency counts do not.

	LP2-05, LP2-11	Insert an archived-notation word delimiter.	Token boundaries and word-based operations may change.

	LP2-07, LP2-15, LP2-38	Insert an archived-notation clause separator.	Clause segmentation and separator-driven reset rules may change.

	LP2-35	Insert an apostrophe in the notation.	Depends on whether the parser retains or splits at that mark.

	LP2-37	Remove four editorial delimiters in the visual-mark profile.	Boundary-dependent counts may change; the rune-only stream is unchanged.


For the seven punctuation-only changes, any calculation using exactly the same rune-only stream receives the same symbols in the same order. This includes whole-page rune frequencies and rune-only n-grams. It does not cover word lengths, punctuation measurements, or a cipher whose key resets at a delimiter. For LP1-10, swapping two runes preserves their combined prime sum but can change local sums and ordered sequences.

A correction is not a whole-page certification

A reviewed layer preserves the documented correction alongside the archive. It does not claim that every rune, dot, color and line on that page has been independently checked. Conversely, no separate layer can mean that no correction was published; it does not establish that nobody inspected the page. The next step toward comprehensive review is to record the region and features examined, including unchanged and uncertain readings.

Use the complete 75-page inventory to inspect layer status, correction notes and exact text hashes. The inventory classifies the stored text; it does not perform a fresh image review. A text hash here is computed from the UTF-8 encoding of the page record’s decoded text, not from a screenshot or an arbitrary downloaded file.

Reproduce the inventory

Extract the reference-data bundle, or use the repository, then run:

python scripts/transcription_coverage.py --check
python scripts/transcription_coverage.py

The standard-library script compares exact text and rune streams separately, records each page-record hash and verifies the saved inventory. Before interpreting a difference, open the linked original page and read the correction note. To compare two actual files, use the comparison commands earlier in this guide.


Do 32 of 55 page breaks split a word?

The archived transcription has 32 rune-to-rune edges among 55 adjacent page boundaries from LP2-00 through LP2-55. This reproduces the numerical count, but does not establish that all 32 fall inside words. A page ending in a rune and the next beginning with one could also cross a section or an unrecorded separator. The denominator excludes the transitions to LP2-56 and LP2-57.

The rule is deliberately simple: take the archived raw layer, remove slash row markers, strip outer whitespace, and compare the two edge characters with the 29-rune alphabet. Retain other punctuation. The complete boundary inventory includes original and processed edge slices, source hashes and all 55 classifications. Every boundary is marked visual review not performed; word join undetermined.

Before using a boundary in a word-edge test, compare both original pages in the reader, check nearby punctuation and section changes, and state whether the test joins or separates them. Where the image remains ambiguous, run both interpretations and report whether the conclusion changes. Can an image detector find a missing line?

A comparison that starts with a supplied list of text rows cannot independently check whether that list contains every row. An image-only detector can propose additional regions, but those regions still need interpretation. In our eight-page row-coverage experiment, a fixed detector matched 43 of 65 manually annotated rune rows. Its other proposals included non-runic text, artwork and several rune rows merged into a single band.

Equal counts can also mislead: LP2-00 had 12 proposals and 12 reference rune rows, yet only nine matched individually. The experiment provides original-image overlays and a reproduction bundle. It tests one segmentation rule; it does not show that a line is missing from the archived transcription.
