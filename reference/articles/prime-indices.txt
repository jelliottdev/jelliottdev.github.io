Prime values and prime indices

Distinguish a prime from its ordinal, and reproduce the 3299 and 9467 calculations.

A prime’s value and its position in the ordered list of primes are different numbers. Specify which operation you mean before combining a prime with a page number or rune value.

Value versus ordinal
Write p_(n) for the nth prime, using one-based indexing: p_(1) = 2, p_(2) = 3, p_(3) = 5. Looking up p_(3299) gives 30,557. This means that 30,557 is the 3,299th prime; it does not mean that 3,299 has ordinal 30,557.
The rune alphabet instead uses zero-based positions 0–28. Rune index i has Gematria Primus value p_(i+1). Confusing these conventions introduces an off-by-one error.

Which way does the lookup go?

There are two different questions: “Which prime is in position 3299?” and “What position does the prime 3299 occupy?” Both use the number 3299, but they return different answers. In the first question, 3299 is an index; in the second, it is a value.

	Prime value	Its one-based position	Equivalent statement

	3299	463	p_(463) = 3299

	7649	971	p_(971) = 7649

	9467	1173	p_(1173) = 9467

	30557	3299	p_(3299) = 30557

	98597	9467	p_(9467) = 98597


For example, replacing the prime value 3299 with its position gives 463. Treating 3299 as a position and looking up the prime there gives 30557. “Take the prime ordinal” is ambiguous unless the direction is stated. The input to an nth-prime lookup need not itself be prime: p_(4) = 7 is perfectly well-defined, although 4 is composite.

The prime-counting function π(x) counts primes less than or equal to x. For a prime q, π(q) is its one-based position. For a composite x, π(x) still exists, but it is not the ordinal of x as a prime. Here π is a function name, not the circle constant.

The 3299 and 9467 examples
The decimal number 3299 appears in red on LP2-15. The arithmetic lookups p_(3299) = 30,557 and p_(9467) = 98,597 are exact. Their product is:
98597 × 30557 = 3012828529
 9857 × 30557 =  301200349
The second expression omits a 9 and gives a different answer. Preserve the operands as well as the final sequence when describing a hypothesis. These calculations establish arithmetic, not a relationship between manuscript pages.

Turning the product into a sequence is another decision

The product is an integer. Reading it as ten separate decimal digits, as five two-digit groups, or as a source of rune shifts gives different inputs. If you choose single digits and add consecutive primes, the first four sums are:

Product digits:     3  0  1  2
Consecutive primes: 2  3  5  7
Sums:               5  3  6  9

Using 0 instead of 7 at the fourth position changes that last sum from 9 to 2. Zero is a valid zero-based rune index for F, but it is not a prime. Such a replacement needs a separate, consistently applied rule: which F positions trigger it, whether they consume a prime, and whether the output is copied or transformed. The interruptions guide explains these alternatives.

Similarly, applying these sums modulo 29 is an additional operation, and applying them as shifts to ciphertext is different from interpreting them directly as rune indices. Write each step explicitly before judging whether the output looks meaningful. A change introduced to improve one fragment must be recorded and checked across the declared scope.

The complete ten-position calculation

Fix one rule: read the product’s decimal digits from left to right and add consecutive primes beginning at 2, without skipping, resetting or replacing any prime. This produces:

	Position	Digit	Prime	Sum

	1	3	2	5

	2	0	3	3

	3	1	5	6

	4	2	7	9

	5	8	11	19

	6	2	13	15

	7	8	17	25

	8	5	19	24

	9	2	23	25

	10	9	29	38


If a separate rule reduces those sums modulo 29, the sequence becomes 5, 3, 6, 9, 19, 15, 25, 24, 25, 9. Only the final sum changes: 38 mod 29 = 9. These residues could be interpreted as direct rune indices or as shifts applied to a specified ciphertext stream, but those are different operations. No ciphertext has been used in this table.

The reproduction script includes the digits, primes, sums and residues in product_digit_prime_addition. This provides a fixed arithmetic reference against which to describe another variant, including an F-triggered exception. The Unicode route discussed below is a separate proposed derivation; neither calculation demonstrates a connection between pages.

From the infinity code point to 7649

The proposed chain starts by identifying a drawn shape with the Unicode infinity character, U+221E, whose code-point value is decimal 8734. That identification and the use of Unicode are hypotheses about how to represent the drawing; the arithmetic that follows does not establish them.

Using the shortest binary spelling gives 14 bits. Flip each bit within that width:

8734: 10001000011110
flip: 01110111100001 = 7649

Equivalently, (2^14 − 1) − 8734 = 7649. This is a fixed-width bit complement, not decimal digit reversal and not reversal of the order of the binary digits. Width is part of the rule: flipping a 16-bit representation instead gives 65535 − 8734 = 56801. A programming-language operator with no declared width can behave differently again.

Next reverse the decimal digits of 7649 to get 9467. Both are primes and differ from one another, so they are emirps. Treating 9467 as a one-based prime index then gives 98597. The separate lookup for 3299 gives 30557, and their product is 3012828529 as shown above. These are individually checkable steps, each with its own representation choice.

What the Unicode names actually say

	Decimal value	Code point	Unicode name
	8734	U+221E	INFINITY
	7649	U+1DE1	COMBINING LATIN LETTER SMALL CAPITAL N
	9467	U+24FB	DOUBLE CIRCLED DIGIT SEVEN

7649 therefore has an N-related character name, but it is not ordinary capital N, whose code point is U+004E, decimal 78. Likewise, a character representing a double-circled seven is not automatically the number seven in a cipher. Turning these names into “N = 7”, then into an instruction to skip a symbol or substitute zero, introduces additional rules that the code-point lookup does not supply. The names can be checked in the official combining-mark chart and enclosed-alphanumeric chart.

How common is the emirp-to-emirp lookup?

Define a finite reference set: all integers from 1000 through 9999 that are prime and whose reversed decimal digits form a different prime. Count individual values, not reversal pairs; exclude palindromic primes. There are 204 such four-digit emirps.

For each value n in that set, calculate the nth prime p_(n), then test whether p_(n) is itself an emirp. Exactly 67 of 204 pass, approximately 32.84%. This independently reproduces the supplied count. The complete audit lists every input, its nth prime, and its pass/fail result.

This is a descriptive proportion for a declared population. It is not a p-value for the manuscript theory. The proposed numbers were not established as uniform random draws from that population, and the chain includes choices of symbol, code point, bit width, digit reversal, lookup direction and output interpretation. Squaring 67/204 would additionally assume two independent draws; that does not follow from selecting two numbers in a theory.

A claim about the prefix 301 would need to define what products were eligible, what counted as a match, and how many alternative transformations and prefixes were inspected. A short fragment that becomes readable only after replacing an inconvenient prime is a fitted result. Preserve that exception and test a fixed rule on new text rather than treating the fitted fragment as an independent confirmation.

Reproduce the chain and reference population

Run python scripts/audit_emirp_chain.py --check from the repository or extracted reference-data bundle. The standard-library script checks the binary widths, Unicode names, nth-prime lookups and all 204 reference cases. It uses exact trial division and makes no network requests. Use --output my-emirp-audit.json to save a new report without replacing an existing file.

This is an arithmetic audit, not a ciphertext experiment. The LP2-15 panel guide preserves the printed numbers; search space and bounds explains how to turn a chain of choices into a testable claim. The suggested subtraction and mirroring routes through pages 0–2 still need exact coordinates and traversal rules before their claimed 301 sequences can be reproduced.
