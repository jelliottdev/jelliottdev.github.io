Magic squares in the 2014 puzzle

Compare the historical 1033 square, the printed LP1-16 square summing to 3301, and signed payload instructions; reproduce the arithmetic.

A magic square has equal sums in every row, every column, and both main diagonals. Its order is its width and height; its magic constant is that common sum. Equal row sums alone are not enough.

Magic does not always mean normal
A normal order-n magic square uses each integer from 1 to n² exactly once. A general magic square need not use that range or distinct entries. Keep the definition separate from any additional rules in a historical challenge.

A documented 1033 square
The archived 2014 walkthrough records this order-5 square during an earlier puzzle stage:
272 138 341 131 151
366 199 130 320  18
226 245  91 245 226
 18 320 130 199 366
151 131 341 138 272
All five rows, all five columns, and both diagonals sum to 1033. Entries repeat, so it is not a normal square. This is historical context, not a newly discovered Liber Primus solution.

The printed 3301 square on LP1-16

The final LP1 sheet contains a five-by-five decimal square below the heading read as CNOW THIS. These are printed numbers, not prime values calculated from runes. The complete instruction reading preserves their position after the text and insect illustration.

1071  280 934  812  204
 966  278 312 1311  434

Every row, every column and both main diagonals sum to 3301. For example, the first row gives 434 + 1311 + 312 + 278 + 966 = 3301; the descending diagonal gives 434 + 812 + 809 + 812 + 434 = 3301. The total of all 25 entries is 16505, which is five times the common line sum. The square is magic under the definition above, but not normal: it repeats values and does not use 1 through 25.

It also has half-turn symmetry: rotate the grid through 180 degrees and every entry returns to an equal entry. In zero-based coordinates, A[r][c] = A[4-r][4-c]. The center, 809, stays in place. This is different from reflecting only left-to-right: the first row reversed is the last row, not the first row. Symmetry and equal sums are separate properties, so both should be checked.

Reproduce the calculation

From the repository folder, run python scripts/check_number_examples.py. No extra packages, network access or AI service are needed. The script reads the five decimal rows directly from the page transcription, checks all twelve line sums and the half-turn, and prints a JSON result under lp1_16. It also records the transcription file hash and the original image hash so another researcher can identify the inputs.

The script verifies arithmetic from the stored transcription; checking those digits against the original JPEG is the independent visual step. These results do not establish that the square supplies a key for an unsolved page or reproduces a historical server submission.

The later LP1 payloads
LP1-10 through LP1-13 contain signed instructions referring to three magic squares. Their ASCII borders differ. If one removes the surrounding border digits, the displayed interior is:
10 12 10
12 14 12
10 12 10
Its row sums are 32, 38, and 32. It is not itself a magic square under the definition above. Do not label the visible number arrangement as a solved magic square merely because the surrounding prose mentions them.
The historical walkthrough later describes an input form accepting squares subject to criteria, with an order-5 square summing to 3301 as one example. This wiki has not independently reconstructed the historical server validator. That report does not prove that the earlier 1033 square was the required submission.

The LP2-15 decimal panel is another distinct arrangement; its printed row and column sums are unequal.
How to check a square

This complete Python 3 example uses the historical arrangement above. It prints row, column, and diagonal totals separately, so a failed check can be located rather than hidden behind a single yes/no result. It needs no files or extra packages.

square = [
    [272, 138, 341, 131, 151],
    [366, 199, 130, 320, 18],
    [226, 245, 91, 245, 226],
    [18, 320, 130, 199, 366],
    [151, 131, 341, 138, 272],
]
n = len(square)
assert n and all(len(row) == n for row in square)
rows = [sum(row) for row in square]
columns = [sum(row[c] for row in square) for c in range(n)]
diagonals = [sum(square[i][i] for i in range(n)),
             sum(square[i][n - 1 - i] for i in range(n))]
lines = rows + columns + diagonals
is_magic = len(set(lines)) == 1
entries = [value for row in square for value in row]
is_normal = is_magic and sorted(entries) == list(range(1, n * n + 1))
print("Rows:", rows)
print("Columns:", columns)
print("Diagonals:", diagonals)
print("Magic:", is_magic, "Normal:", is_normal)
assert lines == [1033] * 12
assert is_magic and not is_normal

Expected output:

Rows: [1033, 1033, 1033, 1033, 1033]
Columns: [1033, 1033, 1033, 1033, 1033]
Diagonals: [1033, 1033]
Magic: True Normal: False

The repository command python scripts/check_number_examples.py checks the same twelve lines alongside the recorded prime-number examples. Either calculation checks arithmetic, not provenance or historical server acceptance.

Where the magic constant comes from

If an order-n square has row sum M, adding all rows gives a total of nM. Thus the total of all entries divided by n is the only possible common row sum. For this example, the total is 5165, so the candidate is 5165 / 5 = 1033. That is a necessary condition, not a substitute for checking the individual lines.

For a normal square, the sum of the integers 1 through n² is n²(n² + 1) / 2. Dividing by n gives the familiar constant n(n² + 1) / 2. A normal order-5 square therefore has constant 65. Applying that formula to this non-normal historical arrangement would be a category error: it does not contain the integers 1 through 25.

Symmetry is a different property

The three-by-three interior in the signed payload looks balanced because it repeats under horizontal and vertical reflection. But its outer rows total 32 while its middle row totals 38. Its columns likewise total 32, 38, and 32; both main diagonals total 34. The total of all entries is 102, giving a candidate constant of 34, yet not one row reaches that value.

	Check	Historical 5 × 5	Payload interior 3 × 3

	All row sums equal?	Yes: 1033	No: 32, 38, 32

	All column sums equal?	Yes: 1033	No: 32, 38, 32

	Both main diagonals match that sum?	Yes: 1033	Both are 34, but the rows and columns fail

	Magic under the stated definition?	Yes	No


A centered layout, repeated numbers, or matching diagonals can be worth describing without calling the arrangement magic. The LP2-15 panel guide applies this same separation between visible pattern and checked sums to its sixteen printed values.
