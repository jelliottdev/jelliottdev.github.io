The Möbius function: squarefree numbers and signs

Distinguish the arithmetic function from a Möbius strip, calculate examples, and specify what a proposed manuscript application would require.

The Möbius function, written μ(n), assigns −1, 0 or 1 to a positive integer according to its prime factorization. It is a different mathematical object from a Möbius strip or the manuscript’s crossed-loop drawing. The word MOBIUS occurs in Some Wisdom; identifying that word does not select which meaning, if any, should become a cipher operation.

The three cases

The definition in NIST’s Digital Library of Mathematical Functions, equation 27.2.12, can be applied as follows:

For n = 1, μ(n) = 1.
If a prime square divides n, μ(n) = 0. For example, 12 contains 2² as a factor.
Otherwise, count the distinct prime factors. With k such factors, μ(n) = (−1)^(k): −1 for odd k, and 1 for even k.

A positive integer with no prime-square divisor is called squarefree. Six is squarefree because 6 = 2 × 3. Twelve is not, because 12 = 2² × 3. Squarefree does not mean prime.

Work through small examples

	n	Factorization	Rule	μ(n)

	1	No prime factors	Defined starting value	1

	7	7	One distinct prime	−1

	6	2 × 3	Two distinct primes	1

	30	2 × 3 × 5	Three distinct primes	−1

	12	2² × 3	A repeated prime factor	0


Compare Euler’s totient φ(n), which counts integers coprime to n. For a prime p, μ(p) is always −1, while φ(p) = p − 1. These functions do different jobs even though both are defined using integer arithmetic.

Reproduce the examples

This trial-division implementation uses Python 3 without extra packages. It is intended for small examples; factoring very large integers is a separate computational problem.

def mobius(n):
    if isinstance(n, bool) or not isinstance(n, int) or n < 1:
        raise ValueError("Use a positive integer")
    sign = 1
    factor = 2
    while factor * factor <= n:
        if n % factor == 0:
            n //= factor
            if n % factor == 0:
                return 0
            sign = -sign
        factor += 1
    return -sign if n > 1 else sign

assert [mobius(n) for n in (1, 7, 6, 30, 12)] == [1, -1, 1, -1, 0]
assert [mobius(n) for n in range(1, 13)] == [
    1, -1, -1, 0, -1, 1, -1, 0, 0, 1, -1, 0
]
print("Examples match")

The code removes a prime factor once, then checks whether it is still present. A second occurrence makes the result zero. Each distinct factor changes the sign; a remaining value greater than one contributes the final prime factor. When the input is 1, no factor is processed and the sign stays 1.

What would applying it to the manuscript mean?

First identify the inputs. Every Gematria Primus rune value is prime, so applying μ separately to those values produces −1 for every rune. That operation loses all distinctions between rune identities. It is not equivalent to applying μ to word sums, printed decimal numbers, or a sequence of positive ordinal positions.

Zero-based rune indices introduce another issue: the F index is 0, outside the positive-integer domain of this definition. Adding one, replacing zero, or choosing prime values instead would each be an additional rule. State it explicitly rather than letting a software convention choose the input.

The function name alone supplies no direction, grouping, starting position, output alphabet or success criterion. A proposed use therefore belongs in a bounded reproducible experiment. This guide explains the mathematics and verifies the examples; it does not claim that μ is an established Liber Primus cipher or that applying it has been exhaustively tested.

LP2-40: the proposed “FOR EVERY” crib

A crib is a guessed plaintext passage, not a recovered reading. One proposal begins by assuming that the first eight runes of LP2-40 mean FOR EVERY, then works backward to a possible running key. The following audit reconstructs its numerical intermediate steps; it does not establish that the guess is correct.

The proposed rune labels are F O R E U E R Y, using U for the English V. Their zero-based indices are [0, 3, 4, 18, 1, 18, 4, 26], and their Gematria Primus sum is 271, a prime. The manuscript’s first eight stored indices are [0, 9, 19, 26, 6, 23, 25, 8]. A prime sum is a property of the proposed spelling; it does not independently identify the plaintext.

Reconstruct the arithmetic

Leave the initial F unchanged. For each remaining proposed plaintext index P, apply (28 − (P + 18)) mod 29: shift by +18, then Atbash. Add the consecutive prime-minus-one schedule starting at 2−1 after the exempt F. These choices reproduce the stated intermediate:

Shift, then Atbash:
0  7  6 21  9 21  6 13

Add prime minus one:
0  1  2  4  6 10 12 16

Intermediate, modulo 29:
0  8  8 25 15  2 18  0

Stored ciphertext:
0  9 19 26  6 23 25  8

Required added key, modulo 29:
0  1 11  1 20 21  7  8

The final row is obtained by subtracting the intermediate from the ciphertext modulo 29. A signed representation may use −8 instead of 21; these are the same residue. This audit exempts only the initial F. It does not infer a rule for later F runes, other interruptions or other pages.

From the repository or reference-data bundle, run python scripts/audit_lp2_40_crib.py. The audit script reads the archived ciphertext and alphabet, prints every stage with input hashes, verifies the prime-minus-one values by coprime counting, and reverses the reconstructed arithmetic back to the proposed crib. It makes no network request and performs no Möbius-driven decryption.

A fitted key is not yet a prediction

For any proposed intermediate X and observed ciphertext C, defining K = C − X (mod 29) guarantees X + K = C. Reconstructing the eight symbols with that fitted key is therefore not an independent test of the guessed words. The evidence would come from a separately specified key-generation rule predicting symbols that were not used to choose it.

The proposed next step assigns different combinations of plaintext, ciphertext and signs to states derived from nearby Möbius values. That needs a complete specification. Each μ value has three possible outputs, so a three-position tuple has up to 27 formal labels before any restrictions from the sequence. Eight binary states do not follow automatically: the conversion to bits, including treatment of zero and sign, must be stated.

A runnable experiment needs the input sequence and starting index, seeds, exact references to previous or current symbols, state-update order, a fixed table mapping every reachable state to an operation, and an interruption rule. It must also state whether it can encrypt and decrypt without consulting the desired answer. Once those choices are frozen, test held-out text or another declared target instead of revising the table whenever a letter misses.

QuagMirrors: distinguish the implementations

QuagMirrors combines keyed alphabet substitutions with changing arithmetic and feedback from preceding symbols. It is a useful example of why an experiment needs a versioned algorithm: the published source contains four implementations with different rules. Their shared name does not make a result from one a test of the others.

This is a source audit, not a decryption result. The files were inspected at revision 88ef1e60b0738b8b28db96bc9dc44dc4da8dd307. Each contains a 729-value ciphertext array and nine hardcoded 29-entry substitution tables. A static check confirms that every table is a permutation of indices 0–28. That establishes that the tables individually map symbols one-to-one; it does not establish that the complete feedback algorithm is invertible or that its output is plaintext.

	Source file	What a reproduction must preserve

	OG_quag_mirror.py	Branches on current and previous Möbius states; a conditional mirror bypass at index 30; stops after 153 loop iterations.

	Mobius_AT_QuagMirror.py	Overrides the first intermediate value and first two mirror selections; stops after six iterations.

	quag_mirror_WIP.py	Uses its own feedback branches and sign convention; contains a cutoff at 500 iterations.

	quag_mirror_v4.py	Explicitly skips index 17 without updating the index or feedback state, then continues with the next ciphertext symbol; stops when its processing index reaches 48.


These are limits and branches visible in the source, not assertions that every program reaches its cutoff successfully. In particular, a skipped ciphertext symbol and an incremented key position are different operations. In v4 the skip is removed from the list before continuing, so the following symbol uses the same processing index. A rewrite that advances the key at that point would test a different algorithm.

How to turn this into a bounded experiment

Choose one file at the pinned revision. Record its exact bytes and dependency versions, and compare its ciphertext array with the archived manuscript transcription before running it.
Record all seeds, substitution tables, exceptional positions, feedback equations and stopping conditions. State which symbols advance each counter.
First reproduce the original output without repairing or extending its rules. If a correction is necessary, save that as a separate variant with an explanation.
Choose the scoring window and success criterion before evaluating new text. Keep the opening used to develop the rules separate from held-out evaluation.
If searching variants, declare the complete set of allowed choices. Repeat that same search on control inputs; comparing the best tuned output with one untuned random output gives an unfair comparison.

For example, allowing three arithmetic operations and twelve substitution choices independently at each of 17 positions creates up to 36^17 operation paths before accounting for duplicate outputs and state constraints. This is an illustrative search bound, not a measured coverage result for these nine-table scripts. The number of distinct outputs may be much smaller, and feedback can make choices dependent. A meaningful experiment must enumerate its actual rules rather than borrowing a probability from a different variant.

Group future results under one QuagMirrors family, with separate records for each frozen implementation and changed variable. No completed QuagMirrors experiment is claimed here. Compare search space and bounds, feedback equations and doublets, and the difference between fitting a crib and predicting new text.
