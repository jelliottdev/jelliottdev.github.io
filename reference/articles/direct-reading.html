Direct reading

When rune labels already form a readable sequence.

Direct reading means that the recorded rune sequence produces readable text without shifting or rearranging its alphabet indices. The runes still need to be identified and labeled correctly. Turning those labels into ordinary English is a separate editorial step.

Identity transformation

Direct reading uses p = c: label each rune without changing its index. Here c is the input rune index and p is the output index in the same 29-symbol alphabet. There is no key to subtract and no permutation to undo. Distinguish the literal labels from contextual English.

Read PARABLE one rune at a time

The first seven runes in the archived LP2-57 sequence produce the heading PARABLE. The reproduction trace gives:

ᚱ44R
ᚪ2424A
ᛒ1717B

ᛖ1818E

Notice what the table does not use: the runes’ prime values. These numbers are zero-based alphabet indices. Prime values are relevant to a separate calculation such as a rune sum, not needed to read this heading.

Why the literal output can still look unfamiliar

Later on LP2-57, the literal labels give LICE, TUNNELNG, and DIUINITY. Contextual English renders these as LIKE, TUNNELING, and DIVINITY. C/K and U/V are label conventions, while the NG rune can stand for the ending represented as ING in ordinary spelling. These readings do not require a new shift of the rune indices.

Keep both forms available. Contextual English makes the passage easier to understand; the rune sequence is the appropriate input for rune counts and prime-sum calculations. Inserting an extra I rune into TUNNELNG would change the numerical input, whereas displaying the same NG rune with a different Latin label would not.

How to replicate

Extract the reference-data ZIP and run these commands with Python 3 from its folder. No extra packages or AI service are needed.

python scripts/reproduce_reading.py some-wisdom
python scripts/reproduce_reading.py loss-of-divinity
python scripts/reproduce_reading.py instruction
python scripts/reproduce_reading.py lp2-57

These cover LP1-05, LP1-10–13, LP1-16 and LP2-57. The loss-of-divinity control includes the documented correction before the identity transformation. That source correction and the cipher operation are separate steps.

To reproduce the heading table and inspect every rune:

python scripts/reproduce_reading.py lp2-57 --trace

The trace’s subtracted_value column is blank because no subtraction is applied. Its copied flag is False: that flag identifies specifically recorded interruption positions, not every rune whose index happens to stay the same. See how to read a trace for all fields.

Readable does not mean exhausted

Several direct-reading pages also have OutGuess payloads. Visual details and numerical patterns need their own evidence. Being able to read the visible words does not establish that every layer of a file has been explained.

Conversely, obtaining familiar letters from a short runic fragment does not establish a direct reading for a whole unsolved page. Compare the complete sequence, word boundaries, and recorded controls before extending a local observation into a broader claim. The identity operation itself is easy to apply to any page; interpreting its output is a different question.
