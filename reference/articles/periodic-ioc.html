Periodic IoC: columns, weighting, and trial periods

A hand-checkable column example, exact-fraction Python reproduction, and the distinction between an ordinary mean and a pooled pair rate.

Periodic IoC groups rune positions by a proposed repeating period and measures coincidence within those groups. It answers a different question from whole-page IoC, which ignores where matching symbols occur. This guide uses an invented seven-symbol example so every count can be checked by hand.

The calculation is a measurement, not a decryption or a demonstrated key-length test for a manuscript page. To evaluate a proposed period, specify how the key advances, how columns are combined, and how many candidates were searched.

A worked example: splitting a trial period into columns

In a simple repeating-key cipher, positions separated by one key period use the same key symbol. Testing a period of two therefore groups positions 0, 2, 4, … into one column and positions 1, 3, 5, … into another. If the proposed period and key-advance rule are right, each column receives a constant shift, which preserves its IoC. This explains why column measurements can be useful; it does not make the highest-scoring trial period the correct one.

Use the invented sequence F U F U F F U. These are seven single-symbol labels for a teaching example, not text from a Liber Primus page. Indexing starts at zero:

ColumnPositionsSymbols
00, 2, 4, 6F F F U
11, 3, 5U U F

Column 0: three Fs contribute 3 × 2 = 6 matching ordered pairs. Its four symbols give 4 × 3 = 12 possible ordered pairs, so IoC is 6/12 = 1/2.

Column 1: two Us contribute 2 matching ordered pairs. Its three symbols give 6 possible ordered pairs, so IoC is 2/6 = 1/3.

There are two different ways to combine these values. The ordinary mean gives each column equal weight: (1/2 + 1/3) / 2 = 5/12 ≈ 0.4167. A pooled pair rate gives each eligible within-column pair equal weight: (6 + 2) / (12 + 6) = 4/9 ≈ 0.4444. The larger column has twice as many ordered pairs, so it contributes twice the weight to the pooled rate.

Pooled column IoC =
    sum(column matching-pair counts)
    / sum(column ordered-pair counts)

Neither number is the whole-sequence IoC. Across all seven positions there are four F symbols and three U symbols, giving (4 × 3 + 3 × 2) / (7 × 6) = 3/7. The whole-sequence denominator includes pairs whose positions belong to different columns. The pooled column denominator excludes them.

Why shuffling matters for columns but not the total

Rearrange the same seven symbols as F F U U F F U. The whole-sequence counts stay four F and three U, so whole-sequence IoC remains 3/7. But the two columns become F U F U and F U F; both have IoC 1/3, and their pooled rate is also 1/3.

This is the distinction a shuffle experiment uses. It preserves the global symbol distribution while changing where symbols fall. A randomization test of column structure can compare an observed column statistic with shuffled versions. It cannot test whether the global IoC itself is unusual under that same shuffle, because that statistic never changes.

For unequal column sizes, specify whether you use the ordinary mean or the pooled rate. A column with fewer than two symbols has no pair and contributes zero to both pooled counts; if every column is that short, the pooled rate is undefined. Very short columns also give unstable estimates, so adding more trial periods is not automatically adding more information.

Reproduce the small example

Save this self-contained Python example as ioc-columns-example.py and run python ioc-columns-example.py. It uses exact fractions and no manuscript inputs or external packages.

from collections import Counter
from fractions import Fraction

def pairs(symbols):
    n = len(symbols)
    matching = sum(c * (c - 1) for c in Counter(symbols).values())
    return matching, n * (n - 1)

def rate(counts):
    matching, total = counts
    return Fraction(matching, total) if total else None

def pooled(symbols, period):
    columns = [pairs(symbols[j::period]) for j in range(period)]
    return rate((sum(a for a, b in columns),
                 sum(b for a, b in columns)))

for text in ("FUFUFFU", "FFUUFFU"):
    print(text, "whole:", rate(pairs(text)), "period 2:", pooled(text, 2))

Expected output:

FUFUFFU whole: 3/7 period 2: 4/9
FFUUFFU whole: 3/7 period 2: 1/3

This example explains an operation, not a tested claim about the manuscript. To apply it, declare the actual rune stream, headings, interruptions, page boundaries, periods and scoring rule first. If you choose the maximum over several periods, each randomized comparison must repeat that same search to evaluate the selected maximum. Comparing the winning period only with a single-period reference would omit the advantage gained by trying many candidates.

To inspect order-dependent local patterns, use repeated rune sequences. Its script lists overlapping bigrams and trigrams with exact positions and input hashes.

Compare with every rearrangement

For this toy example, define the comparison model precisely: retain four Fs and three Us, treat every distinct ordering as equally likely, and measure pooled IoC at the fixed period 2. There are 7! / (4! × 3!) = 35 distinct orderings. This is an assumption about the comparison process, not a claim about how manuscript text was generated.

Pooled IoCOrderingsShare of 35
1/31818/35
4/91212/35
2/344/35

The example’s observed rate, 4/9, is met or exceeded by 12 + 4 + 1 = 17 orderings. Its exact upper-tail probability, including ties, is therefore 17/35 ≈ 0.486 under this model. It is not unusual by that comparison. This probability concerns the statistic under the declared rearrangement model; it is not the probability that a cipher hypothesis is true or false.

Averaging over all 35 scores gives 3/7, the whole-stream IoC. The column lengths stay fixed while the symbols move. Every eligible pair of positions has the same expected match probability, 3/7, even though individual arrangements have different column rates.

Reproduce the exact table

Append this to the small example above, which defines pooled and imports Counter and Fraction. Choosing the four F positions enumerates each distinct ordering once; there is no random seed or simulation error.

from itertools import combinations

distribution = Counter()
for f_positions in combinations(range(7), 4):
    symbols = ["U"] * 7
    for i in f_positions:
        symbols[i] = "F"
    distribution[pooled(symbols, 2)] += 1

assert distribution == {
    Fraction(1, 3): 18, Fraction(4, 9): 12,
    Fraction(2, 3): 4, Fraction(1, 1): 1,
}
total = sum(distribution.values())
observed = Fraction(4, 9)
tail = sum(count for score, count in distribution.items()
           if score >= observed)
assert sum(score * count for score, count in distribution.items()) / total == Fraction(3, 7)
print("Orderings:", total)
print("At least observed:", tail)
print("Upper tail:", Fraction(tail, total))

Expected output: Orderings: 35, At least observed: 17, and Upper tail: 17/35. If you select the best of several periods, this fixed-period table no longer evaluates that selection. Each comparison ordering must undergo the same period search; see null models and selection.

What does changing the offset actually do?

First distinguish a change of labels from a change of input. If every position i stays in the calculation and its column is (i + offset) mod period, changing the offset only renames the columns. The groups of symbols do not change. Their pooled IoC, and the ordinary mean of their defined IoCs, therefore remain unchanged.

For the seven-symbol example and period 2:

Column-label offsetColumn 0Column 1
0F F F UU U F
1U U FF F F U

Both assignments still have 8 matching pairs out of 18 within-column ordered pairs: pooled IoC is 4/9. Searching both offsets under this statistic repeats the same calculation in a different order. It cannot identify which key symbol belongs to the first rune. Actual decoding with a specified key is a different operation, for which key phase can matter.

Dropping a prefix changes the input

If “offset 1” means discarding the first F, the retained stream is U F U F F U. Its two columns are U U F and F F U, giving pooled IoC 1/3. That change comes from removing a symbol, not from discovering a better name for a column. Record the retained positions and their new length when comparing such trials.

A reset at each page boundary is different again. Carrying a period across a three-rune page places the next page’s first rune in column 1 when the period is 2; resetting places it in column 0. If each preceding page length is a multiple of the period, carrying and resetting assign the same columns. See key advancement and boundaries before translating either convention into a decoding rule.

Check the distinction in Python

Append this to the example above. It reuses pairs, rate, and pooled:

def phase_pooled(symbols, period, offset):
    columns = [[] for _ in range(period)]
    for i, symbol in enumerate(symbols):
        columns[(i + offset) % period].append(symbol)
    counts = [pairs(column) for column in columns]
    return rate((sum(a for a, b in counts),
                 sum(b for a, b in counts)))

text = "FUFUFFU"
assert phase_pooled(text, 2, 0) == Fraction(4, 9)
assert phase_pooled(text, 2, 1) == Fraction(4, 9)
assert pooled(text[1:], 2) == Fraction(1, 3)
print("Relabeling preserves 4/9; removing the prefix gives 1/3.")
