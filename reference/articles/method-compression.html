Compression and packed symbol streams

Specify both the conversion into bytes and the format used to decode those bytes.

A proposal may treat the manuscript as encoded compressed data rather than direct language ciphertext. That requires two separate specifications: how visible symbols become bytes, and how those bytes are decompressed. Encryption, compression and a change of numeral base are different operations even when all produce unfamiliar-looking output.

Make the stages explicit

  1. Symbols: choose a verified transcription and alphabet.
  2. Packing: define bit or integer widths, symbol order, byte order and padding.
  3. Format: name the decompressor, framing rules and any dictionary.
  4. Validation: check format constraints and retain the complete output.

For example, indices 0–28 can be represented with five bits each, leaving three unused bit patterns. Eight runes then supply 40 bits, or five bytes, under that particular packing. This does not mean the manuscript uses five-bit packing. Changing bit order or the starting bit offset gives another candidate stream.

Major variants

Variants include fixed-width packing, base-29 integers, dictionary coding, run-length representations and particular compression formats. A raw stream and a file container may need different decoder settings. Arbitrary custom dictionaries can introduce as much freedom as a codebook.

The same symbols produce different bytes

Take the invented symbol indices 0, 1, 2, 3, 4, 5, 6, 7. Five-bit packing writes each index in a field of exactly five bits, concatenates the fields in order and groups the resulting 40 bits into five bytes.

StageRepresentation
Eight five-bit fields00000 00001 00010 00011 00100 00101 00110 00111
Same bits grouped as bytes00000000 01000100 00110010 00010100 11000111
Those bytes in hexadecimal00 44 32 14 c7

Alternatively, treating the same eight indices as base-29 digits gives the integer 638,069,404. Its shortest unsigned byte representation, most significant byte first, is 26 08 2a 9c. That is a different four-byte input. Neither conversion has compressed anything; each has applied a different representation rule.

The shortest integer representation also loses the original count of leading zero digits. To recover this exact eight-symbol sequence, retain its length or another explicit framing rule. Five-bit packing has its own boundary problem when the total bit count is not divisible by eight: specify padding, partial-byte handling and the original symbol count. See radix changes and byte encodings.

Readable output can come from an incomplete stream

A second, independent toy example compresses the ASCII text A complete toy message. with zlib. It does not use the packed bytes above. The script then decodes the complete stream, a copy with its last byte removed, and a copy with five extra bytes appended.

All three return the same readable text in this fixture. Only the first consumes exactly one complete stream with no trailing data. A test that checks only for readable output would miss both differences. This demonstrates decoder behavior on a known sample; it does not estimate how often arbitrary manuscript candidates would be accepted.

Python's zlib documentation distinguishes eof, unused_data after a stream, and unconsumed_tail left by an output limit. Keep those separate. A concatenated-stream format may legitimately use trailing data, but requires a declared rule to process it.

Reproduce the examples

Run python scripts/compression_example.py. The script uses Python's standard library, checks the packing round trip and all three decoder cases, and records the compressed input bytes and zlib version. Download the script · Download the report.

The decoder call limits this small fixture to 4,096 output bytes. For a real search, set a total output budget across all calls and classify a limit hit separately from a malformed stream. Python's initial buffer-size setting is not a total decompression limit.

What a test must specify

Fix the symbol-to-number mapping, packing, alignment, endianness, padding, format, decoder version and dictionary. Bound the number of combinations. Set an output-size limit when testing decompression so a malformed candidate cannot exhaust memory.

A decoder accepting bytes is only the first check

Record errors and complete outputs. Check declared lengths, checksums where the format provides them, end-of-stream handling and whether trailing bytes are ignored. Use known compressed samples and controls passed through the same packing search. High entropy alone does not identify compression.

Documented experiments

The direct-rune compression test found no complete decompression using three fixed packings and five formats. It starts at byte zero; other offsets, formats and transformations before packing are outside that test. Rune entropy and byte encoding explain the measurements and representations used to define such tests.
