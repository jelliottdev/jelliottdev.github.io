The image hidden in LP1-03

The decoded JPEG, its archived rune transcription, and exact reproduction steps.

LP1-03 has two different images to examine: the visible runic manuscript page and a smaller JPEG encoded inside its signed OutGuess message. The known Vigenère reading of the manuscript does not automatically decode the second image.

Four layers to keep separate

	Layer	What you examine
	Original LP1-03 JPEG	The visible Welcome page, with its runes and leafy border. It also carries hidden data.
	OutGuess payload	31,809 extracted bytes containing the signed message.
	Signed message body	A short instruction followed by hexadecimal text representing another JPEG.
	Decoded JPEG	The small rune-and-digit image shown below, 15,188 bytes long.

The body opens with “Let the text guide you.”, then “Good luck.” and “3301”, before the hexadecimal sequence. These words are in the extracted message, not the visible runic paragraph on the manuscript sheet. Read the complete body or inspect the signed block.

OutGuess extraction, signature verification, and hexadecimal decoding answer different questions. Extraction retrieves the stored bytes. Signature verification checks the signed content against a particular public key. Hexadecimal decoding converts character pairs into bytes. None of those operations alone supplies a reading of the runes in the resulting image.

The decoded derivative

The JPEG decoded from the hexadecimal portion of LP1-03’s signed message.
The derivative is 587 × 109 pixels and 15,188 bytes. Download the JPEG. Its checksum is recorded in the payload manifest.

Archived transcription
The pinned iBotPeaches archive supplies this transcription:
ᚦᛗᛞᛇᚠᛗᚪᚱ5ᚢᚫᛝᚱᛝ3 ᛠᛗᛇᚠᛡ
It contains 18 runes and the decimal digits 5 and 3. In the wiki’s alphabet labels, with spaces inserted between individual symbols for clarity:
TH M D EO F M A R 5 U AE NG R NG 3 EA M EO F IA
Those labels are a transliteration, not established plaintext. The added spaces above identify symbol boundaries; they are not a new claim about word boundaries in the image. Decimal digits remain digits rather than becoming rune indices.

How to reproduce the image
First follow OutGuess extraction for LP1-03 and verify its signed message. Decode the hexadecimal suffix of the exported body:
import hashlib
import json
from pathlib import Path

manifest = json.loads(
    Path("data/evidence/embedded-payloads.json").read_text(encoding="utf-8")
)
record = next(row for row in manifest["records"] if row["page"] == "lp1-03")
body_bytes = Path(record["body_path"]).read_bytes()
if hashlib.sha256(body_bytes).hexdigest() != record["body_sha256"]:
    raise ValueError("Message body differs from the recorded source")
body = body_bytes.decode("utf-8")
image = bytes.fromhex(body[body.index("ffd8ffe"):])
if len(image) != record["embedded_image_bytes"]:
    raise ValueError("Decoded JPEG length differs from the record")
if hashlib.sha256(image).hexdigest() != record["embedded_image_sha256"]:
    raise ValueError("Decoded JPEG differs from the recorded derivative")
with open("lp1-03-decoded.jpg", "xb") as output:
    output.write(image)
print("Verified and wrote", len(image), "bytes")
The exclusive-create mode refuses to overwrite an existing file. This reproduces a format conversion, not a proposed solution to the image’s text. Keep the original signed body and the derivative as separate files.

Run the example from an extracted reference-data bundle or the repository root. It uses only Python’s standard library. A successful run prints Verified and wrote 15188 bytes. The hashes check consistency with the supplied manifest; authenticate the signed message separately using the linked verification instructions.
If a hash check fails, stop before interpreting the derivative. Confirm that the message body and manifest come from the same download, and avoid opening and resaving the body in an editor that changes line endings. Use the file-verification guide to compare bytes. The checks deliberately read the body as bytes before decoding its text.
