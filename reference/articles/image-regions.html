An image region specifies where a measurement was made. Keeping the rectangle, original image, and measurement rule together lets another person inspect the same pixels.

Reading a rectangle

The wiki uses [x, y, width, height] in original-image pixels. The origin is the top-left; x increases rightward and y downward. For [599, 664, 153, 501], the region starts at x = 599, y = 664 and covers 153 columns and 501 rows. In a half-open crop convention, the right and bottom bounds are 752 and 1165.

A thumbnail or resized preview uses different display coordinates. Use the original JPEG or the wiki’s region inspector rather than copying screen coordinates into a dataset.

Pixel dimensions and density metadata

All 75 manuscript originals are 2400 × 3600 pixels. This inventory covers LP1-00–16 and LP2-00–57, including their title and chapter pages. It does not include thumbnails, illustration crops, the separate illustrated cover, or later-message images.

The nine unitless files are LP1-00, 01, 02, 03, 08, 10, 11, 12 and 13. Their 1 × 1 density metadata describes an aspect ratio; it does not mean one pixel per inch. The other 66 files declare 400 pixels per inch in both directions. The Pillow JPEG documentation explains the jfif_unit and jfif_density fields used in the check.

Pixels are not a physical production history

At a declared 400 pixels per inch, 2400 × 3600 pixels would map to 6 × 9 inches. That is a conversion from metadata, not evidence that the manuscript was printed or scanned at that size. Software can set or change density metadata without changing the pixel grid. These fields also do not identify which software created the images.

For geometric comparisons, use original pixel coordinates first. The same dimensions provide a common canvas, but do not guarantee that two drawings share an origin, scale or alignment. For example, the side-dot comparison on LP2-40–55 separately establishes equality within two fixed rectangles; the dimensions alone would not establish that result.

Connected components

A connected component is a group of selected pixels joined by the chosen neighborhood rule. Eight-connectivity includes horizontal, vertical, and diagonal neighbors. Four-connectivity excludes diagonal neighbors; the same image can produce different counts under those definitions.

The published opening-page measurement uses foreground grayscale below 140 and retains eight-connected groups containing at least 20 pixels. Tiny isolated specks are excluded by that area threshold. A count of 13 means thirteen qualifying groups under this rule, not necessarily thirteen intentional dots.

Connectivity is transitive: the two outer pixels need not touch each other to belong to the same group. A path through the middle pixel is enough. This is why a thin diagonal bridge can merge what a person sees as separate marks.

Reproduce the small mask

This Python 3 example counts all selected pixels, with no minimum-area filter. It needs no image package:

def component_areas(points, diagonal=False):
    remaining = set(points)
    neighbors = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    if diagonal:
        neighbors += [(1, 1), (1, -1), (-1, 1), (-1, -1)]
    areas = []
    while remaining:
        pending = [remaining.pop()]
        area = 0
        while pending:
            x, y = pending.pop()
            area += 1
            for dx, dy in neighbors:
                neighbor = (x + dx, y + dy)
                if neighbor in remaining:
                    remaining.remove(neighbor)
                    pending.append(neighbor)
        areas.append(area)
    return sorted(areas)

pixels = {(0, 0), (1, 1), (2, 2)}
assert component_areas(pixels) == [1, 1, 1]
assert component_areas(pixels, diagonal=True) == [3]
assert component_areas(set()) == []
print("Four-connected:", component_areas(pixels))
print("Eight-connected:", component_areas(pixels, diagonal=True))

Each selected pixel is removed from the remaining set when it is assigned to a component, so it cannot be counted twice. The reported areas total three under either rule. Connectivity changes grouping, not how many foreground pixels exist.

The real opening-page rule additionally discards components smaller than 20 pixels. Applied to this tiny teaching mask, that filter would retain zero components under either connectivity rule. Always report the neighborhood, brightness threshold and minimum area together; “three dots” is not a complete measurement specification.

Measure the five dots on LP2-56

The five isolated dots below the hash-target text provide a manageable first measurement. The rectangle [800, 2350, 900, 500] contains the dots without the writing above them. Its coordinates refer to the original 2400 by 3600 pixel image.

Download and extract both the reference data and original images into the same directory. Run these commands there, with Python 3 installed:

python -m pip install Pillow
python scripts/measure_region.py lp2-56 --rect 800 2350 900 500 --threshold 140 --minimum-area 20 --connectivity 8

The script checks the original JPEG against the page record’s SHA-256 before decoding it. It converts the pixels to grayscale with Pillow, selects values strictly below 140, groups eight-connected neighbors, and discards groups smaller than 20 pixels. It prints JSON and leaves the image unchanged.

With Pillow 11.3.0, the region contains 17,888 selected pixels in five retained components; no small components are discarded. The table lists them from top to bottom by centroid. These row numbers are measurement labels, not a proposed reading order.

A centroid is the arithmetic mean of the selected pixels’ x and y indices. It estimates the center of this dark pixel group, not an intended geometric point. The table rounds to three decimal places for readability; the complete JSON result retains six decimals, bounding rectangles, input hash, Pillow version and all measurement settings.

To measure another region, change the page ID and rectangle. Keep the output with your notes, including any settings you change. A rectangle that cuts through a dot measures only the retained part; a threshold that admits a connecting stroke can merge groups. Comparing two patterns also requires a stated rule for matching points and allowing translation, rotation or scaling. Five components alone establish none of those relationships.

Color classification

Within a stored rectangle, foreground pixels use the weighted brightness test 0.299R + 0.587G + 0.114B < 140. A foreground pixel is red-dominant when R − max(G,B) > 70. A red-dominant fraction above 90% gives “red”; below 10% gives “dark”; intermediate cases are “mixed/uncertain.” These labels summarize pixels under a rule, not a chemical analysis of ink.

What a successful recount establishes

Matching a recorded count confirms that the stated operation reproduces it on the stored rectangle and exact image bytes. It does not prove that the rectangle includes every relevant mark or that two overlapping rectangles should be interpreted as one character. Segmentation, symbol identification, and cipher interpretation are separate decisions.

Reproduce the published examples

Follow the LP2-00–02 inventory and run python scripts/inspect_visual_records.py --pixels. The measurement manifest records the scope and input hashes; the script shows the exact implementation. Keep file integrity separate from a claim about meaning.
