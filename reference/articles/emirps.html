Emirps and decimal reversal

Check reversed primes without conflating reversal, mirroring, and prime lookup.

An emirp is a prime whose decimal digits, reversed, form a different prime. Both primality and the difference condition matter. This is a property of a number’s decimal representation, not a cipher by itself.

Examples and non-examples

13 and 31 form an emirp pair. 11 is prime but palindromic, so it is not an emirp under this definition. 23 is prime, but its reverse 32 is composite. The pair 7649 and 9467 passes both prime checks.

Keep decimal reversal distinct from mirroring an image, reversing rune order, complementing digits, and taking a prime ordinal. Decimal reversal of 8734 is 4378. A transformation from 8734 to 7649 therefore needs a separately specified rule; “invert” alone does not define it.

Where this matters in the manuscript

The spelling and prime-sum article computes the three LP2-57 body sentence totals under a declared rune-only convention and checks their reversals. The boundaries and counting convention belong to the claim. Finding an emirp after changing a boundary is a different test.

The infinity character and 8734

The Unicode Mathematical Operators chart lists the infinity character as U+221E. The digits after U+ are hexadecimal: E represents fourteen. Converting the code point to decimal gives:

0x221E = 2 × 16³ + 2 × 16² + 1 × 16 + 14 = 8734

That conversion is exact for the Unicode character ∞. Choosing that character to represent the open crossed-loop drawing on LP2-15 is a separate hypothesis. A picture in a JPEG does not inherently have a Unicode code point, even when it resembles a familiar symbol.

Specified operationResult
Convert hexadecimal 221E to decimal8734
Reverse the decimal digits of 87344378
Replace each decimal digit d with 9 − d1265
Negate the integer 8734−8734
Reverse the decimal digits of 76499467

These are different operations, although several might informally be called “inverting.” None of the first four gives 7649. A proposed route from 8734 to 7649 therefore needs its own explicit transformation; the fact that 7649 and 9467 are both prime does not supply that missing step.

A code point is not a byte sequence

The same infinity character has code-point value 8734 and UTF-8 bytes E2 88 9E. The former is a number assigned to the character; the latter is one encoding of it. Reversing decimal digits, reversing hexadecimal characters, and reversing encoded bytes are distinct tests. Always record which representation is being used before applying a numerical operation.

This Python 3 check reproduces the character conversion, byte encoding, and two decimal transformations without any external package:

symbol = "\u221e"
value = ord(symbol)
reverse = int(str(value)[::-1])
complement = "".join(str(9 - int(d)) for d in str(value))
print(value)                          # 8734
print(symbol.encode("utf-8").hex(" ")) # e2 88 9e
print(reverse)                        # 4378
print(complement)                     # 1265
assert value == int("221E", 16) == 8734
assert reverse == 4378
assert complement == "1265"

For the later, independently checkable steps of the 301 calculation, see the two nth-prime lookups and their product. Keeping a correct multiplication separate from an unspecified earlier transformation makes the hypothesis easier to investigate.

How to replicate the predicate

from math import isqrt
def prime(n):
    return n >= 2 and all(n % d for d in range(2, isqrt(n) + 1))
def emirp(n):
    reverse = int(str(n)[::-1]) if n >= 0 else -1
    return n != reverse and prime(n) and prime(reverse)
assert emirp(7649)
assert not emirp(11)

Converting the reversed digits to an integer removes leading zeros. This convention must be stated if applying reversal to strings that are not already prime numbers. See prime indices and selection effects.
