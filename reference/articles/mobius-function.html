The Möbius function: squarefree numbers and signs

Distinguish the arithmetic function from a Möbius strip, calculate examples, and specify what a proposed manuscript application would require.

The Möbius function, written μ(n), assigns −1, 0 or 1 to a positive integer according to its prime factorization. It is a different mathematical object from a Möbius strip or the manuscript’s crossed-loop drawing. The word MOBIUS occurs in Some Wisdom; identifying that word does not select which meaning, if any, should become a cipher operation.

The three cases

The definition in NIST’s Digital Library of Mathematical Functions, equation 27.2.12, can be applied as follows:

  1. For n = 1, μ(n) = 1.
  2. If a prime square divides n, μ(n) = 0. For example, 12 contains 2² as a factor.
  3. Otherwise, count the distinct prime factors. With k such factors, μ(n) = (−1)k: −1 for odd k, and 1 for even k.

A positive integer with no prime-square divisor is called squarefree. Six is squarefree because 6 = 2 × 3. Twelve is not, because 12 = 2² × 3. Squarefree does not mean prime.

Compare Euler’s totient φ(n), which counts integers coprime to n. For a prime p, μ(p) is always −1, while φ(p) = p − 1. These functions do different jobs even though both are defined using integer arithmetic.

Reproduce the examples

This trial-division implementation uses Python 3 without extra packages. It is intended for small examples; factoring very large integers is a separate computational problem.

def mobius(n):
    if isinstance(n, bool) or not isinstance(n, int) or n < 1:
        raise ValueError("Use a positive integer")
    sign = 1
    factor = 2
    while factor * factor <= n:
        if n % factor == 0:
            n //= factor
            if n % factor == 0:
                return 0
            sign = -sign
        factor += 1
    return -sign if n > 1 else sign

assert [mobius(n) for n in (1, 7, 6, 30, 12)] == [1, -1, 1, -1, 0]
assert [mobius(n) for n in range(1, 13)] == [
    1, -1, -1, 0, -1, 1, -1, 0, 0, 1, -1, 0
]
print("Examples match")

The code removes a prime factor once, then checks whether it is still present. A second occurrence makes the result zero. Each distinct factor changes the sign; a remaining value greater than one contributes the final prime factor. When the input is 1, no factor is processed and the sign stays 1.

What would applying it to the manuscript mean?

First identify the inputs. Every Gematria Primus rune value is prime, so applying μ separately to those values produces −1 for every rune. That operation loses all distinctions between rune identities. It is not equivalent to applying μ to word sums, printed decimal numbers, or a sequence of positive ordinal positions.

Zero-based rune indices introduce another issue: the F index is 0, outside the positive-integer domain of this definition. Adding one, replacing zero, or choosing prime values instead would each be an additional rule. State it explicitly rather than letting a software convention choose the input.

The function name alone supplies no direction, grouping, starting position, output alphabet or success criterion. A proposed use therefore belongs in a bounded reproducible experiment. This guide explains the mathematics and verifies the examples; it does not claim that μ is an established Liber Primus cipher or that applying it has been exhaustively tested.

LP2-40: the proposed “FOR EVERY” crib

A crib is a guessed plaintext passage, not a recovered reading. One proposal begins by assuming that the first eight runes of LP2-40 mean FOR EVERY, then works backward to a possible running key. The following audit reconstructs its numerical intermediate steps; it does not establish that the guess is correct.

The proposed rune labels are F O R E U E R Y, using U for the English V. Their zero-based indices are [0, 3, 4, 18, 1, 18, 4, 26], and their Gematria Primus sum is 271, a prime. The manuscript’s first eight stored indices are [0, 9, 19, 26, 6, 23, 25, 8]. A prime sum is a property of the proposed spelling; it does not independently identify the plaintext.

Reconstruct the arithmetic

The audit script reads the archived ciphertext and alphabet, prints every stage with input hashes, verifies the prime-minus-one values by coprime counting, and reverses the reconstructed arithmetic back to the proposed crib. It makes no network request and performs no Möbius-driven decryption.

A fitted key is not yet a prediction

For any proposed intermediate X and observed ciphertext C, defining K = C − X (mod 29) guarantees X + K = C. Reconstructing the eight symbols with that fitted key is therefore not an independent test of the guessed words. The evidence would come from a separately specified key-generation rule predicting symbols that were not used to choose it.

The proposed next step assigns different combinations of plaintext, ciphertext and signs to states derived from nearby Möbius values. That needs a complete specification. Each μ value has three possible outputs, so a three-position tuple has up to 27 formal labels before any restrictions from the sequence. Eight binary states do not follow automatically: the conversion to bits, including treatment of zero and sign, must be stated.

A runnable experiment needs the input sequence and starting index, seeds, exact references to previous or current symbols, state-update order, a fixed table mapping every reachable state to an operation, and an interruption rule. It must also state whether it can encrypt and decrypt without consulting the desired answer. Once those choices are frozen, test held-out text or another declared target instead of revising the table whenever a letter misses.
