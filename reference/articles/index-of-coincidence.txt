Index of coincidence: a reproducible rune baseline

Matching-pair counts for every archived page, exact inputs, scaling, invariants and interpretation limits.

The index of coincidence (IoC) measures how often two different positions in a text contain the same symbol. It summarizes the symbol distribution; it does not read the text or identify a cipher by itself. This guide provides a reproducible whole-page baseline for the archived Liber Primus runes.

Count matching pairs

Let N be the number of runes and nᵢ the count of rune i. The unscaled convention used here is:

IoC = sum(nᵢ × (nᵢ − 1)) / (N × (N − 1))

There are N × (N − 1) ordered choices of two distinct positions. A rune occurring nᵢ times contributes nᵢ × (nᵢ − 1) matching choices. Dividing gives the probability of a match when sampling positions without replacement. Counting unordered pairs instead divides both quantities by two and produces the same result.

For the three-symbol sequence F F U, only the two F positions match. The numerator is 2 and the denominator is 6, so IoC is 1/3. For F U it is 0; for F F it is 1. With zero or one symbol there is no pair to draw, so IoC is undefined. The JSON uses null in that case.

Exactly what this baseline counts

Each page is measured separately using its archived text/lp…txt file.
Only the 29 symbols in the published rune alphabet count. A rune with a multi-letter Latin label is still one symbol.
All archived runes count, including rune headings. Punctuation, whitespace, line-wrap markers, Latin text and printed decimal numbers do not.
No transcription corrections, decryption, heading removal or page concatenation are applied. This is an archived-stream baseline, not a plaintext baseline.
A page with no archived rune transcription and a recorded count of zero has an undefined IoC. This does not imply that its image or embedded payload has no information.

Every record contains the input path and SHA-256, the rune count, a 29-entry frequency array, the numerator, denominator and IoC. The array follows the alphabet order stored in the same report. Its alphabet hash covers the UTF-8 concatenation of those 29 runes without separators. Unknown symbols in the Unicode Runic block cause an error rather than being silently discarded.

What is the reference level?

For independent, uniformly distributed symbols from a 29-symbol alphabet, the expected match probability is 1/29 ≈ 0.03448276. This follows by adding the 29 possible matching outcomes, each with probability (1/29)². A finite sample need not equal this expectation. An observed value below it is possible; LP2-31 is one example.

The report also supplies scaled_ioc_29 = 29 × IoC, whose uniform independent expectation is 1. Always state whether a number is scaled. Do not compare this rune statistic directly with an English A–Z benchmark: the alphabet, multi-letter symbols, encoding and inclusion rules differ.

What it can and cannot distinguish

Reordering a fixed set of symbols leaves its frequency counts unchanged. A transposition therefore preserves whole-stream IoC. A one-to-one substitution renames symbols but preserves their multiplicities, so it also preserves IoC. This includes Atbash and a constant modular shift. Equality of IoC does not establish which of these transformations, if any, was used.

A changing substitution, such as a repeating-key Vigenère operation, can change the distribution. A value near the uniform reference is nevertheless not proof of Vigenère, randomness or strong encryption. A higher value does not prove plaintext or a monoalphabetic cipher. Different processes can produce similar frequency distributions.

Whole-page measurements can mix regions with different rules. A heading may be unencrypted while the body is encrypted. Joining pages introduces cross-page pairs, so the combined IoC is not generally the simple average of page values. A corrected glyph can change counts. Record these choices before comparing results.

Turning a baseline into an experiment

A periodic analysis would divide positions into columns under a stated period and starting offset, then compare column distributions. That is a separate procedure from the whole-page calculation here. It requires explicit punctuation handling, page boundaries, column lengths and an aggregation rule. Testing many periods and reporting only the largest value creates a selection effect.

Before making a significance claim, specify a null model that matches the actual question. Shuffling the same rune stream cannot test whether its global IoC is unusual, because every shuffle has exactly the same counts. It can be useful for an order-sensitive statistic, such as a specified column analysis, but that experiment needs its own recorded method and results.

This baseline reports descriptive measurements only. It supplies no p-values, cipher classification, key-length estimate or new solution. A technique search belongs in Have we tried it? only when its scope and results are documented through the experiment process.

A worked example: splitting a trial period into columns

In a simple repeating-key cipher, positions separated by one key period use the same key symbol. Testing a period of two therefore groups positions 0, 2, 4, … into one column and positions 1, 3, 5, … into another. If the proposed period and key-advance rule are right, each column receives a constant shift, which preserves its IoC. This explains why column measurements can be useful; it does not make the highest-scoring trial period the correct one.

Use the invented sequence F U F U F F U. These are seven single-symbol labels for a teaching example, not text from a Liber Primus page. Indexing starts at zero:

	Column	Positions	Symbols	Matching ordered pairs	All ordered pairs	IoC

	0	0, 2, 4, 6	F F F U	6	12	1/2

	1	1, 3, 5	U U F	2	6	1/3


There are two different ways to combine these values. The ordinary mean gives each column equal weight: (1/2 + 1/3) / 2 = 5/12 ≈ 0.4167. A pooled pair rate gives each eligible within-column pair equal weight: (6 + 2) / (12 + 6) = 4/9 ≈ 0.4444. The larger column has twice as many ordered pairs, so it contributes twice the weight to the pooled rate.

Pooled column IoC =
    sum(column matching-pair counts)
    / sum(column ordered-pair counts)

Neither number is the whole-sequence IoC. Across all seven positions there are four F symbols and three U symbols, giving (4 × 3 + 3 × 2) / (7 × 6) = 3/7. The whole-sequence denominator includes pairs whose positions belong to different columns. The pooled column denominator excludes them.

Why shuffling matters for columns but not the total

Rearrange the same seven symbols as F F U U F F U. The whole-sequence counts stay four F and three U, so whole-sequence IoC remains 3/7. But the two columns become F U F U and F U F; both have IoC 1/3, and their pooled rate is also 1/3.

This is the distinction a shuffle experiment uses. It preserves the global symbol distribution while changing where symbols fall. A randomization test of column structure can compare an observed column statistic with shuffled versions. It cannot test whether the global IoC itself is unusual under that same shuffle, because that statistic never changes.

For unequal column sizes, specify whether you use the ordinary mean or the pooled rate. A column with fewer than two symbols has no pair and contributes zero to both pooled counts; if every column is that short, the pooled rate is undefined. Very short columns also give unstable estimates, so adding more trial periods is not automatically adding more information.

Reproduce the small example

Save this self-contained Python example as ioc-columns-example.py and run python ioc-columns-example.py. It uses exact fractions and no manuscript inputs or external packages.

from collections import Counter
from fractions import Fraction

def pairs(symbols):
    n = len(symbols)
    matching = sum(c * (c - 1) for c in Counter(symbols).values())
    return matching, n * (n - 1)

def rate(counts):
    matching, total = counts
    return Fraction(matching, total) if total else None

def pooled(symbols, period):
    columns = [pairs(symbols[j::period]) for j in range(period)]
    return rate((sum(a for a, b in columns),
                 sum(b for a, b in columns)))

for text in ("FUFUFFU", "FFUUFFU"):
    print(text, "whole:", rate(pairs(text)), "period 2:", pooled(text, 2))


Expected output:

FUFUFFU whole: 3/7 period 2: 4/9
FFUUFFU whole: 3/7 period 2: 1/3

This example explains an operation, not a tested claim about the manuscript. To apply it, declare the actual rune stream, headings, interruptions, page boundaries, periods and scoring rule first. If you choose the maximum over several periods, each randomized comparison must repeat that same search to evaluate the selected maximum. Comparing the winning period only with a single-period reference would omit the advantage gained by trying many candidates.

Sources and verification

Historical background: William F. Friedman, The Index of Coincidence and Its Applications in Cryptanalysis, preserved by the NSA. The counting convention and derivation used by this script are stated explicitly above; do not assume every historical or modern use of “IoC” has identical scaling.
