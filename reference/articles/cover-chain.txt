The LP1 three-image chain: response, XOR and columns

Recover the first three manuscript JPEGs from the archived response, then combine their signed payloads and reorder the resulting ciphertext.

Looking for the cover with compasses? See the illustrated cover and its Blake artwork. It is separate from the title pages discussed here.

Before the three images: the preserved server response

The compasses-cover RSA replay produces a historical address. A pinned archive preserves one short response capture and a later complete capture from that stage. The second begins with <!--761-->, followed by hexadecimal data. These are hosted source files, not current responses from the old address.

Decode the complete response’s hex, XOR every resulting byte with 0xFF, and split the 1,820,649-byte result into segments of 168,876, 1,476,614, and 175,159 bytes. Reverse the byte order of the third segment. The three outputs match the original JPEGs for LP1-00, LP1-01, and LP1-02 byte for byte. Splitting first or omitting the third reversal fails that exact comparison.

	168,876–1,645,489	None	LP1-01 JPEG

	1,645,490–1,820,648	Reverse all segment bytes	LP1-02 JPEG


Run python scripts/replay_2014_onion_response.py --check after extracting the reference-data bundle. Add --extract-dir recovered-pages to save the three checked JPEGs without overwriting existing files. The script, replay report and source manifest pin every input and output hash. The archive’s original notes are preserved too.

The 541-byte first capture contains only 256 decoded hex bytes and is not a prefix of the complete response. The archive describes a changing response, but these two files alone do not establish its exact update schedule. The replay begins from the saved complete capture and makes no request to the historical service.

XOR corresponding bytes
What XOR means, with a worked byte example.
XOR produces a 0 bit when input bits agree and 1 when they differ. Compute result[i] = A[i] XOR B[i] XOR C[i] on decoded bytes, not on hexadecimal text characters. For example, 0x0f XOR 0x33 = 0x3c.
python scripts/reproduce_cover_chain.py
python scripts/reproduce_cover_chain.py --output combined.asc
The script checks input and output hashes and refuses to overwrite files. Its 991-byte result is another signed message, requiring its own signature check.

Follow the first byte
The first decoded bytes are 77, 17, and 4d in hexadecimal. Pairing the same position in each stream gives:
0x77 XOR 0x17 = 0x60
0x60 XOR 0x4d = 0x2d
0x2d is the ASCII hyphen, the first character of the reconstructed PGP header. This checks one position only; the script checks the SHA-256 hash of the complete reconstruction. Decode the hex pairs first: XORing the character codes for the printed digits would use different inputs.
All three streams must have equal lengths. Do not pad a short stream, cycle it, or quietly discard unmatched bytes. If lengths disagree, check the extracted bodies and their hashes before proceeding.
Read the columns
Remove spaces from the first two ciphertext lines and arrange the 70 characters in five rows of fourteen:
IDGTKUMLOOARWO
ERTHISUTETLHUT
IATSLLOUIMNITE
LNJ7TFYVOIUAUS
NOCO5JI4MEODZZ
Within each row, take columns in zero-based order 2, 8, 9, 1, 12, 13, 11, 4, 5, 7, 3, 0, 6, 10. Concatenate the five reordered rows from top to bottom. This transposition gives:
GOODWORKULTIMATETRUTHISTHEULTIMATEILLUSIONJOINUSATFV7LYUCMEOZZD5J4ONIO

Follow the first four column selections
The first source row is IDGTKUMLOOARWO. Columns begin at zero, so column 0 contains I, column 1 contains D, and column 2 contains G. Apply the supplied order to that row:
	Output position	Source column	Character
	1	2	G
	2	8	O
	3	9	O
	4	1	D
The first four selected characters spell GOOD. Continue with the remaining ten column indices, then apply the same complete order to each of the next four rows. Here, output positions in the table count from one for readability, while source columns use the zero-based convention required by the script.
The instruction “read the columns” can otherwise be ambiguous: this recipe reorders characters within each row, then joins the rows. It does not read one entire vertical column from top to bottom before moving to the next.
Preserve the literal ending
The exact output ends in ONIO. The historical walkthrough restores a final N to render fv7lyucmeozzd5j4.onion. That character is an interpretation, not a permutation output. This is a historical address, not a claim of current reachability.
The supplied permutation reproduces the known result. It does not show that a unique ordering can be inferred without clues or applied to another page.
