OutGuess extraction

Choose the correct original image, extract its hidden payload, check the expected bytes, and follow the signed message to its next step.

OutGuess retrieves a hidden payload from an image file. A visible title, artwork, or runic passage can coexist with a separate signed message inside the JPEG. Extracting that message is a different operation from decoding the visible runes.

Choose the image first

Two different images are often called “the cover.” The illustrated compasses collage is 1033.jpg; the plain Liber Primus title page is LP1-00. They have different hidden messages and different extraction sizes.

Expected size of the full extraction, not the JPEG or separated message body

Equal byte counts do not mean equal messages. Use the expected SHA-256 for the specific image’s extraction, as recorded in its manifest.

Prepare the files and tool

  1. Use a repository checkout, or extract both the reference-data ZIP and original-images ZIP into the same directory. Keep their scripts/, data/, and images/ folders intact.
  2. Install or build OutGuess for your operating system. The downloads contain reproduction scripts, not an OutGuess executable. The recorded extraction used the pinned upstream source.
  3. Open a terminal in the directory containing those folders. Use Python 3 to run the wrapper below. If OutGuess is not on PATH, replace outguess after --outguess with its full executable path, quoted if it contains spaces.

Use the original JPEG, not a screenshot, thumbnail, or image saved through an editor. Resizing or recompressing the image can change the carrier bytes even when it looks the same.

Run one extraction

Choose one command for the file you want to inspect:

python scripts/extract_payload.py opening-2014 --outguess outguess --output opening-payload.bin
python scripts/extract_payload.py 1033 --outguess outguess --output compasses-payload.bin
python scripts/extract_payload.py lp1-00 --outguess outguess --output title-payload.bin

The wrapper first checks the original image’s hash. It then extracts into a temporary file using the literal key string Default key, compares the resulting payload hash with the recorded control, and saves your output only if they match. It refuses to overwrite an existing destination. The script makes no network or AI request.

For LP1-00, the underlying retrieval command is:

outguess -r -k "Default key" images/lp1-00.jpg title-payload.bin

Running OutGuess directly does not perform the wrapper’s input or output checksum checks. A successful retrieval message is therefore not equivalent to a match with the published control.

What success looks like

The wrapper prints Verified 2899 bytes. SHA-256: … for LP1-00, with the full checksum rather than the ellipsis. For 1033, expect 1,498 bytes; for opening-2014, expect 1,150. This establishes that the extracted bytes match the archived control. It does not verify a PGP signature or explain the message body.

Keep the output layers separate

File layerPurposeNext operation
Original JPEGPreserves the visible image and hidden-data carrierCheck its hash, then extract

.signed.ascPreserves the separated signed messageVerify the signature
.body.txtContains the message body as a derivativeInterpret or decode the body’s specific format

The wiki supplies these layers separately in the payload inventory. Preserve the extraction unchanged. For LP1-00–02, the bodies are hexadecimal inputs to the three-image chain. For the compasses cover, the body supplies RSA parameters; for the opening image, it supplies book-cipher coordinates.

If the command fails

  • Python cannot find the script: check your working directory and extracted folder structure.
  • The OutGuess executable cannot be found: supply its full path. Having Python installed does not install OutGuess.
  • Input JPEG differs from the pinned original: obtain the original from Downloads and check that you selected the correct image.
  • Output already exists: choose a new output filename. The wrapper preserves existing results.
  • Extraction returns different bytes: retain the diagnostic, executable version, and input hash. The wrapper does not save unverified output under your requested destination.

Verified coverage

The collection records ten default-key extractions: eight LP1 images checked on 19 October 2026 and the opening image and compasses collage checked on 20 October. This is a positive inventory of reproduced payloads, not an exhaustive search of every image, key, or steganographic method.
