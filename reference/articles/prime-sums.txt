Reproducing rune prime sums

Compute exact sentence and word totals, test explicit spelling changes, and keep arithmetic separate from intent.

A prime-sum claim is a claim about a particular sequence of runes under a particular counting rule. Before asking why a spelling was chosen, establish which text was counted and whether the claimed total can be reproduced. The spelling reference discusses individual cases; this guide walks through the calculation.

Choose the input layer

The page record’s ordinary prime sum describes its archived runes. For an encrypted page, this is a ciphertext sum. The examples here instead use the known decoded rune sequence, with the documented correction and cipher rules applied. These are different quantities even when both are called “the page sum.”

Use the rune’s Gematria Primus prime value, not its zero-based cipher index. Count each rune once. The rule here excludes spaces, punctuation, line-wrap markers and printed decimal numbers. A Latin label such as IA or NG denotes one rune; it must not automatically become two individual letter-runes.

Run the read-only check

python scripts/reproduce_prime_sums.py
python scripts/reproduce_prime_sums.py --json

Run from the repository or the extracted reference-data ZIP using Python 3. See script setup if this is your first command. The first prints a concise report. The second prints the full rune sequences, prime values, totals and counterfactual results as JSON. Neither command changes files, accesses the network, or calls an AI.

The script re-decodes the nine documented controls, verifies all 17 literal page readings, reconstructs the rune stream from the per-rune trace, and compares the ten selected word occurrences and four LP2-57 segments with the published arithmetic evidence. The ten occurrences are the examples selected for the spelling article, not an exhaustive sample of all manuscript words. This shares the known-reading implementation; it is not an independent photographic transcription.

LP2-57: boundaries change the claim

For LP2-57, remove archive line-wrap markers and divide at the archive’s periods. This gives a heading followed by three body segments:

	Segment	Sum	Reversal	Result
	PARABLE heading	449	944	Prime sum, composite reversal
	First body sentence	1259	9521	Emirp
	Second body sentence	1031	1301	Emirp
	Third body sentence	1229	9221	Emirp

An emirp must be prime, and its decimal reversal must be a different prime. Combining heading and body gives 449 + 1259 + 1031 + 1229 = 3968, which is even and greater than 2, hence composite. Including the heading therefore changes the proposition from three emirp sentence sums to a composite page total. There is no contradiction: the boundaries differ.

What does a spelling change actually do?

Start with the exact original sequence, specify an alternate sequence, and subtract their totals. For a replacement of one rune by several, the change is the sum of the inserted rune values minus the removed rune value.

Worked example: CWESTIAN

The second word of the Instruction reading on LP1-16 contains seven runes. In the labels used by the arithmetic evidence, they are C, W, E, S, T, IA and N. The final three Latin letters in “TIAN” therefore do not represent three separate runes: IA is one alphabet entry worth 107.

C    W    E    S    T    IA    N
13 + 19 + 67 + 53 + 59 + 107 + 29 = 347

Reverse the decimal digits: 347 → 743
Both are prime, and they are different: 347 is an emirp.

Now construct an alternative that represents the sound with separate I and O runes. Keep every other rune fixed. Their combined value is 31 + 7 = 38, so replacing 107 with 38 gives 347 − 107 + 38 = 278. This is a real arithmetic difference. Writing the original rune’s label as IO instead of IA, or C as K, would leave the underlying seven runes and their sum unchanged. See transliteration conventions before comparing Latin spellings.

Compare the other cases

TUNNELNG → a separate I before NG: adding I contributes 31. The first LP2-57 sentence changes from 1259 to 1290. The alternate total is composite. NG/ING is a multi-letter rune convention, so this comparison does not establish that the original is a spelling error.

CWESTIAN with one IA/IO rune → separate I and O: remove 107 and add 31 + 7. The change is −69; the word total becomes 347 − 69 = 278, composite. Simply relabeling C as K or IA as IO changes no rune and therefore no sum.

WIDSOM → WISDOM: exchanging D and S changes no values or multiplicities. The total remains 270. A reordering cannot make this additive total prime.

BELIEUE ↔ BELEIUE: exchanging I and E also preserves the total, 369. The documented transcription correction is important for source fidelity and order-sensitive ciphers; it does not tune the additive sum.

These alternatives are explicitly constructed comparisons. They are not additional text found on the manuscript.

A quick arithmetic check

Only the F rune has the even prime value 2; every other rune value is odd. The sum is odd exactly when the number of non-F runes is odd. An even total greater than 2 cannot be prime. This provides a quick necessary check before trial division, not a sufficient test: many odd totals are composite.

Adding I flips parity because 31 is odd. Reordering a word cannot change parity or any other property of its additive total. Keeping those invariants explicit helps distinguish a meaningful numerical change from a visually different spelling with identical arithmetic.

What this says about purpose

For the manuscript’s philosophical use of the term, see primality and divinity. A prime-valued alphabet provides numerical context, but does not by itself specify which sums the prose asks a reader to calculate.

The reproducible observation is that the three body sums are emirps under the declared convention. The counterfactuals show that some alternate encodings lose a property, while reorderings and aliases do not affect it. Neither statement alone identifies the author’s reason for choosing a spelling.

Could a prime sum act as a consistency check?

That is one possible purpose: if a reader knew in advance that each sentence should have an emirp sum, a sentence with a composite sum would signal a mismatch with that rule. The reader could then check the transcription, rune interpretation and sentence boundary. In the first LP2-57 sentence, inserting a separate I changes 1259 to 1290, so this proposed check would reject that particular insertion.

Passing would be much weaker evidence. “The sum is an emirp” accepts many different totals. Even an exact expected total accepts any rearrangement of the same runes. WIDSOM and WISDOM both total 270: a sum cannot tell which order the manuscript uses. It also loses information beyond order. For example, the synthetic two-rune sequences U–O and TH–TH both total 10: 3 + 7 = 5 + 5. These are different rune collections with the same length and total, not manuscript words or a proposed reading.

A useful check therefore needs an independently justified expectation, not just a property discovered after trying different boundaries. It can help reject some candidate transcriptions; it cannot recover the wording by itself. Compare what cipher operations preserve and file checksums, which address a different question: whether the file bytes match a specified reference.

A proposed purpose such as marking sentence boundaries or providing a consistency check needs a separately stated rule and a complete set of cases. It should explain which units are meant to satisfy the rule and which choices were allowed. Selecting only successful words, or adding a delimiter value after seeing a composite total, changes the test. See selection effects and reproducible scope. This guide does not assign a probability that the observed totals were intentional.
