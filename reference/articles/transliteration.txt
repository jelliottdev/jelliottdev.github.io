Transliteration and literal readings

Keep manuscript symbols separate from the decisions made while interpreting them.

Different text layers
A transcription records runes. A transliteration replaces each rune with a Latin label. A cipher transformation may produce plaintext rune indices, whose labels form a literal decoded reading. Contextual English can normalize spelling or interpret those labels. It is an editorial layer.
Transliterating encrypted runes does not decrypt them. Conversely, direct-reading sections need no nontrivial substitution.

Compare the right outputs
Begin with the image and archived rune text. Record corrections before applying a cipher. Compare a literal output with the page-level control, not a normalized paragraph spanning several pages. Preserve spelling when testing prime sums.
On LP1-10, a documented I/E order correction matters. The script swaps runes at zero-based ordinals 116 and 117; it does not rewrite every similar sequence. See the transcription guide.

Compare the representations

Archived rune row:
ᚦᚳᛒᛝᛏᛉᛡᛞ-ᛋᛡ-ᚩᚠ.ᛈᛖᛞᛋᛁ-ᛚᛁᚻᚾᛝᚱ-/

Latin labels, with archive delimiters retained:
THCBNGTXIAD-SIA-OF.PEDSI-LIHNNGR-/

The archive row has 29 Unicode characters: 23 rune symbols, four hyphens, one period and one slash. This count excludes the newline that separates rows in the text file. The final slash records a line boundary; it is not an additional rune drawn at the right edge of the image. The other delimiter names follow the archive’s transcription convention.

The first four runes have labels TH · C · B · NG. Those are four symbols but six Latin letters. Concatenating the labels as THCBNG loses their individual boundaries unless the mapping is kept alongside them. Indexing that string one English letter at a time would therefore change the unit being analyzed. See rune indices and prime values.

Reproduce the counts

From an extracted reference-data bundle or repository checkout, save this as a Python file in the root directory and run it there. It uses only Python’s standard library and reads the preserved transcription:

import json
from collections import Counter
from pathlib import Path

index = json.loads(Path("data/index.json").read_text(encoding="utf-8"))
labels = {item["rune"]: item["latin"] for item in index["alphabet"]}
row = Path("text/lp2-31.txt").read_text(encoding="utf-8").splitlines()[0]
runes = [char for char in row if char in labels]
other = Counter(char for char in row if char not in labels)
print("Archived characters:", len(row))
print("Runes:", len(runes))
print("Other characters:", dict(other))
print("First four labels:", [labels[char] for char in runes[:4]])

Expected output:
Archived characters: 29
Runes: 23
Other characters: {'-': 4, '.': 1, '/': 1}
First four labels: ['TH', 'C', 'B', 'NG']

Selecting only runes is appropriate for the published rune-frequency calculation. It is not a faithful copy of every visible feature. Keep the original row when testing punctuation, spacing or boundaries, and state whether a key advances on runes only or on another declared unit. A transcriber’s separator does not decide that rule for you. See printed marks and exported characters.
