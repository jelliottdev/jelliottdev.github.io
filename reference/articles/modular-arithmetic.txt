Arithmetic modulo 29

How shifts wrap around the rune alphabet, including negative results.

The rune alphabet has 29 positions, numbered 0 through 28. Arithmetic modulo 29 keeps a calculation within those positions by wrapping around whenever it passes either end. It supplies the arithmetic used by several documented readings, including Vigenère and prime-minus-one.

What “mod 29” means
Two integers are equal modulo 29 when their difference is a multiple of 29. For rune indices, choose the representative from 0 through 28. Moving forward from 28 by one returns to 0; moving backward from 0 by one returns to 28.

Worked steps
If ciphertext index c is 3 and the key value is 10, then p = (3 − 10) mod 29 = 22. First subtract normally to get −7. Then add 29 to choose the equivalent value in the allowed range. The negative intermediate result is not an error.

	Calculation	Ordinary result	Adjustment	Rune index

	28 + 1	29	Subtract 29	0

	0 − 1	−1	Add 29	28

	3 − 10	−7	Add 29	22

	21 − 256	−235	Add 9 × 29	26


The final row is a calculation from the LP2-56 trace. Eight additions of 29 leave −3; the ninth reaches 26. Adding 29 only once would also leave a negative number. A modulo operation handles however many complete turns are needed.

Different numbers can describe the same shift

A shift by 31 is equivalent to a shift by 2 because 31 = 29 + 2. Subtracting 23 is equivalent to adding 6 because −23 + 29 = 6. This explains how two walkthroughs can describe the same operation using different signed amounts.

Equivalence depends on the entire formula. Adding 23 and subtracting 23 are generally different. For input index 0, they produce 23 and 6 respectively. Do not change the direction while keeping the same key values and expect the same reading.

Modulo 29 is also different from writing a number in base 29. Modulo retains one residue; a base-29 representation expresses the whole number using place values. Likewise, reducing a Gematria Primus prime value modulo 29 does not generally recover the rune’s alphabet index. The value and index are separate assignments.

Python and JavaScript examples

For integer inputs and a positive divisor of 29, Python’s % gives the representative from 0 through 28:

def mod29(n):
    return n % 29

assert mod29(-7) == 22
assert mod29(-235) == 26
assert mod29(29) == 0
assert mod29(31) == 2
assert all(mod29(n) == mod29(n + 29) for n in range(-100, 101))

JavaScript’s % is a signed remainder operation: -7 % 29 gives −7. Normalize the result before using it as an alphabet index. The JavaScript remainder reference documents this distinction.

const mod29 = n => ((n % 29) + 29) % 29;

for (const [input, expected] of [[-7, 22], [-235, 26], [29, 0], [31, 2]]) {
    if (mod29(input) !== expected) throw new Error("Incorrect residue");
}

These examples are self-contained checks for small integers, not whole-page decoders. For an actual control, run python scripts/reproduce_reading.py lp2-56 --trace from the reference-data setup and inspect the input, subtracted value, and output columns.

Check a shift by undoing it

If decoding subtracts k, adding k back should recover the input modulo 29. For the example above, (22 + 10) mod 29 = 3. A round-trip check is useful for catching a sign or normalization mistake:

for c in range(29):
    for k in range(29):
        p = (c - k) % 29
        assert (p + k) % 29 == c

This verifies the arithmetic for every single-rune input and shift. It does not verify a keyword, a page transcription, or the handling of an interruption. Those choices belong to the complete decoding method.

Multiplication needs an inverse, not ordinary division

An affine map has the form y = (ax + b) mod m: multiply by a, add b, then reduce modulo m. To undo it on all residues, first subtract b, then multiply by the modular inverse of a. An inverse is an integer u satisfying au ≡ 1 (mod m). It is not the fraction 1/a.

For example, 2 has inverse 15 modulo 29 because 2 × 15 = 30 ≡ 1. If y = (2x + 3) mod 29 and x=20, the output is 14. Recover x with 15 × (14 − 3) mod 29 = 20. Dividing the displayed output difference 11 by 2 would give 5.5 and miss the wraparound.

An inverse exists exactly when gcd(a,m)=1, where the greatest common divisor is the largest positive integer dividing both numbers. Such a residue a is called a unit modulo m. If the gcd is one, integers u and v exist with au + mv = 1, making u an inverse. Conversely, any inverse equation gives that same integer identity, so a common divisor must divide 1.

Because 29 is prime, every multiplier from 1 through 28 has an inverse modulo 29. Zero does not. Composite moduli require the gcd check; a nonzero multiplier is not automatically invertible.

Invertible on all residues versus distinct on one page

Two inputs x and z collide under an affine map when a(x−z) ≡ 0 (mod m); adding b does not affect collisions. Let d=gcd(a,m). Dividing both a and m by d leaves coprime integers, so the condition is exactly that x−z is a multiple of m/d. If d is greater than one, the full residue set therefore has collisions.

A smaller input set can still avoid those colliding pairs. The LP2-55 experiment supplies two concrete examples:

	Map	gcd(a,m)	Colliding input pair	On the page

	(58x + 57) mod 114	2	2 and 59 both give 59	59 is absent; the 25 observed prime inputs give 25 distinct outputs

	(102x + 101) mod 202	2	2 and 103 both give 103	103 is absent; the 25 observed prime inputs give 25 distinct outputs


Neither multiplier has an inverse on its full residue set. Nevertheless, each map is injective on the page’s observed support. A lookup table could reverse it within that restricted input set. This is why requiring a whole-ring inverse would reject these two maps even though the experiment’s weaker, explicitly stated condition allows them. Their existence is not evidence of recovered plaintext.

Check both meanings in Python

Run this from the extracted reference-data bundle or repository with Python 3.8 or later. The negative exponent in three-argument pow requests a modular inverse.

import json
from math import gcd
from pathlib import Path

assert pow(2, -1, 29) == 15
assert (15 * (((2 * 20 + 3) % 29) - 3)) % 29 == 20
alphabet = json.loads(Path("data/index.json").read_text(encoding="utf-8"))["alphabet"]
prime = {entry["rune"]: entry["prime"] for entry in alphabet}
text = Path("text/lp2-55.txt").read_text(encoding="utf-8")
support = {prime[c] for c in text if c in prime}
assert len(support) == 25
for a, b, m in [(58, 57, 114), (102, 101, 202)]:
    assert gcd(a, m) == 2
    assert len({(a*x+b) % m for x in range(m)}) == m // 2
    assert len({(a*x+b) % m for x in support}) == len(support)
print("PASS: no full-residue inverse, but distinct outputs on LP2-55 support")

This snippet checks the two named maps. The experiment’s separate certificate is what establishes that they are the only nonidentity affine maps in its all-modulus search; the snippet alone does not prove completeness.

What this does not decide
Modulo arithmetic supplies wraparound, not the key, direction, offset, or interruptions. See Vigenère, prime-minus-one, and keystream positions.
