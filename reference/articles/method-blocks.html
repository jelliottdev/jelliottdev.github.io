Block and matrix transformations

Transform groups of runes together instead of treating each position independently.

A block method transforms several symbols at once. Matrix multiplication modulo an alphabet size is one possibility; pair-based lookup rules are another. Sharing a block size does not make these mechanisms equivalent.

Major variants

Families include Hill-style linear maps, affine block maps, keyed digraph tables and explicit polygraphic codebooks. Their parameter counts, invertibility conditions and treatment of repeated letters differ.

A reversible two-symbol example

Represent a block as a column of two rune indices x and y. This invented encoder uses the matrix with rows [1, 2] and [3, 5], modulo 29:

first output  = (x + 2y) mod 29
second output = (3x + 5y) mod 29

Input [4, 7] gives [18, 18]: the second raw sum is 47, which reduces to 18. The determinant is 1 × 5 − 2 × 3 = −1, a nonzero residue modulo the prime 29, so the matrix has an inverse. Its inverse has rows [24, 2] and [3, 28]. Applied to [18, 18], it recovers [4, 7].

This operates on pairs, not independently on each symbol. Two unequal inputs in a block can produce equal output indices without contradicting reversibility of the whole block. Equality-pattern arguments for a single-symbol substitution cannot simply be transferred to this model.

One matching block leaves many keys

Suppose the matrix is unknown and the only proposed plaintext/ciphertext pair is [4, 7] → [18, 18]. Writing the unknown rows as [a, b] and [c, d] gives two equations in four unknown entries:

4a + 7b = 18 (mod 29)
4c + 7d = 18 (mod 29)

Each choice of a and c fixes b and d because 7 has an inverse modulo 29. That gives 841 matrices, of which 812 are reversible. A matching pair therefore does not identify one key in this model.

[4, 7] → [18, 18]812One nonzero input/output pair.
Above, plus [8, 14] → [7, 7]812The second pair is twice the first modulo 29; it adds no constraint.
First pair, plus [1, 0] → [1, 3]1The independent second input fixes the remaining freedom.

The last row identifies a unique matrix only within this declared linear two-symbol model and the supplied alignments. If both plaintext pairs were guessed or selected from many alternatives, uniqueness after fitting is not independent evidence that they were correct. Test the resulting key on an untouched continuation. Other block sizes, affine offsets and lookup-table rules remain different hypotheses.

Reproduce the counts

python scripts/matrix_crib_example.py

The standard-library script checks both round trips for all 841 two-symbol inputs under the example key. It then enumerates all 841 matrices satisfying the first pair, retains the 812 with nonzero determinant, and applies the two additional constraints separately. Download script · Download report. What a test must specify

Fix alphabet, modulus, block size, orientation, block alignment and padding. For a matrix decoder, establish invertibility under that modulus; over a composite modulus a nonzero determinant alone is insufficient. Keep table-based rules distinct from linear ones.

How to evaluate a result

First round-trip known plaintext through the proposed encoder and decoder. Then test whether enough independent constraints exist to identify parameters. Keys fitted to one block require validation on additional blocks not used in fitting.

Documented experiments

The direct Hill-key test found no invertible two- or three-rune matrix that turns any of the 55 nonempty page starts into one of nine fixed 12-rune openings. This checks every possible key for those alignments: independent blocks determine a candidate matrix, and later blocks contradict it. Other openings, block offsets, affine additions and changing keys remain outside the result.
