2012: telephone primes, countdown and coordinates

Follow the prime product and compare two cicada JPEGs with independently extracted payloads.

The Reddit book code supplied a telephone number. The next clue sent solvers back to the original JPEG, then onward to a website whose image changed between stages. This walkthrough separates the reported telephone instruction from the image extractions we can reproduce now.

From the telephone clue to a domain

The archived telephone account and recording describe an instruction to multiply three primes associated with final.jpg, naming 3301 as one. The original image is 509 pixels wide and 503 pixels high. Both dimensions are prime, so 509 × 503 × 3301 = 845145127. That number supplied the historical domain label 845145127.com.

The opening-image audit reads those dimensions from the preserved JPEG and checks primality and multiplication. A resized copy could destroy this clue. The telephone instruction is historical source evidence; this replay did not call the number or verify the recording independently.

Two files with the same-looking artwork

[Image: Locations-stage JPEG: a visually similar black cicada with spread wings.]
Locations carrier: 20,892 bytes. Download preserved JPEG.

These previews look alike, but the files have different hashes and different hidden messages. A fresh OutGuess extraction from each file exactly matched its corresponding archived payload. This does not claim that their decoded pixels are identical, or that the byte-length difference alone identifies the hidden content.

	Carrier	Extracted bytes	Message content
	Countdown	1,001	A return time: 17:00 UTC on 9 January 2012
	Locations	1,221	Twelve latitude/longitude pairs

The stage archive associates these with the countdown and subsequent location publication. It distinguishes the payload’s coordinate list from additional locations reported on the webpage. The count of twelve here applies only to these extracted bytes, not every reported poster location.

Preserve the coordinate notation

The payload is a PGP cleartext-signed message. Its final coordinate line starts - -33.90281, 151.18421. The first dash and following space are cleartext escaping; removing that prefix leaves a negative latitude. Removing both dashes would move the point into the northern hemisphere. This format handling does not itself verify the signature.

Another line separates the two numbers with whitespace rather than a comma. The coordinate ledger retains each original line alongside its parsed latitude and longitude, so the parsing decisions remain visible. It does not assign street addresses or claim that posters were independently confirmed at those points.

Repeat the extraction

Extract the reference-data ZIP. With Python 3, check the two carriers, stored payloads and coordinate parsing:

python scripts/replay_2012_countdown.py --check

To run OutGuess yourself, supply an installed executable. The script uses temporary output files and compares the newly extracted bytes with the preserved payloads:

python scripts/replay_2012_countdown.py --check --outguess /path/to/outguess
