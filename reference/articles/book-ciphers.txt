Book ciphers: coordinates, editions and counting rules

How text lookups work and what to preserve so another reader can reproduce them.

A book cipher turns coordinates into text by looking them up in a shared source. The source can be an essay, poem or other document; it need not be a whole book. To reproduce a result, knowing the title is not enough. You also need the edition and the rules used to count its parts.

How a four-part lookup works

In a paragraph:sentence:word:letter scheme, 2:1:3:2 means: select paragraph 2, then its first sentence, then its third word, then the second letter of that word. This assumes one-based counting, where the first item is numbered 1.

For a small invented example, let paragraph 2 begin We study runes. The third word is runes, so the second letter is u. The coordinates identify nested locations; they are not numbers to add together.

The archived 2014 opening puzzle uses this kind of rule with Emerson’s Self-Reliance. That guide traces all 15 coordinates and the literal characters against a derivative of the referenced PDF, with downloadable source files and a reproduction script.

Reproduce the small example

The nested lists below explicitly define paragraphs, sentences, and words. That makes the counting visible; this example does not pretend to automatically recognize those boundaries in an arbitrary PDF. The words contain only letters, so character positions and letter positions agree here.

# document[paragraph][sentence][word]
document = [
    [["First", "paragraph"]],
    [["We", "study", "runes"]],
]

def lookup(document, coordinate):
    if len(coordinate) != 4 or any(type(n) is not int or n < 1 for n in coordinate):
        raise ValueError("Use four positive one-based integer coordinates")
    p, s, w, letter = coordinate
    try:
        word = document[p - 1][s - 1][w - 1]
        character = word[letter - 1]
    except IndexError as error:
        raise ValueError(f"Coordinate out of range: {coordinate}") from error
    return word, character

coordinate = (2, 1, 3, 2)
word, character = lookup(document, coordinate)
print(coordinate, word, character)
assert (word, character) == ("runes", "u")
# (2, 1, 3, 2) runes u

The subtraction of 1 converts each published coordinate to Python’s zero-based indexing. Validate positivity before subtracting: an input coordinate of zero would otherwise become index −1, which Python interprets as the last item. An invalid coordinate could silently produce a plausible letter instead of failing.

	Sentence	1	0	We study runes

	Word	3	2	runes

Decide what counts before extracting

Starting point
State whether titles, opening quotations and notes are included. Starting at the first prose paragraph can differ from starting at the first text on the page.

Paragraph boundaries
Preserve actual paragraph divisions. A page or display line ending may interrupt a paragraph without creating a new one.

Sentence boundaries
Specify how punctuation and abbreviations are handled. Splitting blindly at every period can create false sentences.

Word and letter boundaries
Record how hyphens, apostrophes, punctuation and accented letters are treated. Counting characters in a raw file is not necessarily counting letters in the printed word.

Literal characters
A clue may print some digits or punctuation directly. Identify those separately instead of forcing every item through the coordinate rule.

For example, the raw characters in don't put the apostrophe in position 4 and t in position 5. Counting letters only instead puts t in position 4. Neither convention should be introduced only after seeing which one gives a desired output. Define it for the whole extraction and retain the original spelling.

Why a different edition can change the result

A text with the same title can differ in paragraph divisions, punctuation, added notes, or corrected spelling. In a nested coordinate system, these differences act at different levels: a new paragraph can shift paragraph coordinates, an altered sentence boundary can shift sentence coordinates within that paragraph, and a changed word can affect its letter positions.

A matching PDF checksum establishes that two researchers started from the same file. It does not establish that their PDF-to-text tools produced the same paragraphs. Preserve the extracted derivative and its rules as well as the source file. The Emerson replay provides a concrete example of keeping the source PDF, paragraph data, lookup rule, and output trace together.

What a reproducible trace should show

For each coordinate, record the selected paragraph, sentence, word and letter, plus the resulting output character. Include the source URL, a file checksum, and any transcription changes. A reader should be able to inspect one disagreeing character without rerunning an opaque decoder.

If a coordinate points beyond a sentence or word, report it as out of range. Wrapping around, skipping a heading or switching editions introduces another rule. Such a rule may be worth testing, but it must be stated rather than hidden inside a correction.

Using a possible literary reference

A recognizable quotation or artwork can suggest a source to investigate. It does not identify the indexing scheme. Before trying many passages and counting conventions, write down the source, coordinates, transformations and success criterion. Otherwise a promising fragment may simply be the best-looking result among many undocumented choices.
