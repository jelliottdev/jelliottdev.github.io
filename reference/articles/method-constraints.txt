Constraint solving, SAT and SMT

Encode a bounded cipher model, distinguish satisfying assignments from confirmed readings, and check contradictions and uniqueness.

Constraint solving expresses a proposed decoding rule as variables, allowed values and conditions that must all hold. The solver then searches for assignments satisfying those conditions. It can help reject incompatible cribs or recover keys inside a specified model. It does not supply the missing cipher specification.

Write the model before asking for a solution

For a fixed substitution on 29 symbols, define a variable f[x] for each input index. Require each value to lie between 0 and 28. If the mapping is a permutation, require all 29 values to be different. A proposed plaintext index p[i] at ciphertext position c[i] adds the condition f[c[i]] = p[i].

Dropping the all-different condition permits several ciphertext symbols to map to the same plaintext symbol. Giving each position its own mapping permits still more freedom. These are different models; a solution to one does not establish a solution to the original permutation model. See fixed substitutions, many-to-one substitutions and adaptive rules.

One crib, six keys, one contradiction

This invented five-symbol example is small enough to enumerate without a solver library. The ciphertext is 0, 1, 0. We test all 5! = 120 permutations of the alphabet 0–4.

	Conditions added	Remaining full keys	Interpretation
	None	120	Every alphabet permutation is allowed.
	First output must be 2	24	Fixing f[0] leaves four values to assign.
	Second output must be 3	6	Three unused input symbols can still map to the remaining values in 3! ways.
	Third output must be 2	6	This repeats the first condition and adds no information.
	Instead, third output must be 4	0	The same input 0 cannot map to both 2 and 4 under a fixed mapping.

All six keys in the compatible case produce the same output on this short ciphertext. A unique output on the observed symbols is therefore not a unique complete key. Conversely, the contradictory crib excludes only that crib under the fixed-mapping assumptions. It does not exclude a position-dependent cipher.

Download the enumeration script. Run python scripts/constraint_example.py from the repository root to reproduce the counts and save the complete surviving mappings. This demonstration is not an unsolved-page experiment.

Read the solver's answer at the right scope

	Outcome	What it establishes	What remains to check
	Satisfiable	At least one assignment satisfies the encoded conditions.	Replay it through an independent decoder; inspect the full output and untested continuation.
	Unsatisfiable	The asserted conditions cannot all hold, if they were encoded correctly and the solver's result is sound.	State every domain, crib and restriction. The result applies only to their conjunction.
	Unknown, timeout or interrupted	No conclusive answer was obtained.	Record the reason, limits and any partial candidates; do not report exclusion.

SAT tools work with Boolean conditions; SMT tools also support specified mathematical theories. The official Z3 introduction explains its role in logical modeling, and its basic commands guide documents satisfiable, unsatisfiable and unknown outcomes. The example here uses exhaustive Python enumeration instead.

Check alternatives, not just the first answer

Finding one key does not show that it is unique. To ask for another, forbid that exact key assignment and solve again under unchanged conditions. A second satisfying assignment disproves uniqueness; an inconclusive run does not prove it. Decide whether uniqueness concerns the entire key, its action on observed symbols, or the decoded text. Unused alphabet entries and auxiliary variables can differ without changing the reading.

If a contradiction depends on a guessed word, the word is one of the assumptions. If a model was constructed to force a whole sentence, reproducing that sentence is also expected. Test additional material that was not used to construct the conditions. See cribs and candidate readings and unrestricted keys.

What a test must preserve

Publish the exact input, variable domains, equations, mapping direction, boundary rules and crib positions. Distinguish hard requirements from scoring preferences. Retain solver version, options, limits, returned status and assignment. Check the encoding against known positive and contradictory examples before applying it to the manuscript.

A practical workflow is to solve a small case by enumeration, compare it with the solver model, and independently replay every reported candidate. For larger negative claims, retain any available proof artifact or independently checkable certificate and describe how it was checked. A log saying “no solution” alone does not expose the assumptions or verify the model.
