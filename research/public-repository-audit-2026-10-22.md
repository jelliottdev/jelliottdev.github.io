# Public repository intake, 22 October 2026

This is a worklist for source review, **not** a count of completed Liberpedia experiments or a census of every public Cicada idea.

The [candidate snapshot](public-repository-candidates.json) records three GitHub repository-name/description searches. They returned 94, 130 and 232 hits respectively; after deduplication, **327 repositories** are candidates. Search metadata alone says nothing about whether a repo contains original tests, copied files, runnable code, or valid conclusions. Repositories on other hosts, and even some known GitHub repos such as [Wulfic/Cicada3301-Liber_Primus](https://github.com/Wulfic/Cicada3301-Liber_Primus), did not match these queries. Do not describe the 327 as “all public repositories.”

## First source inspected

[Dukotah/cicada3301](https://github.com/Dukotah/cicada3301/tree/f08b20b632d91209ddbaa747e8e2f23df0c78ba1), pinned at commit `f08b20b632d91209ddbaa747e8e2f23df0c78ba1`. Its [machine-readable ledger](https://github.com/Dukotah/cicada3301/blob/f08b20b632d91209ddbaa747e8e2f23df0c78ba1/liber-primus/LEDGER.json) is 553,757 bytes (SHA-256 `7718bf90fb4cc6cc0fb98464d65ab898dd0e776da33d9b056bcd908d3b60558d`). It has **172 entries**: 49 labelled measured, 48 negative, 25 audit, 20 open, 15 partially run, 7 never run, 5 eliminated and 3 superseded. These are the repository's own statuses. In its negative category, 31 entries name a reproduction command and 44 name evidence files; their files, commands, controls, and findings require source-specific checks. The replays linked below cover only their declared portions.

The ledger mixes research questions and units of work. Some statuses also refer to an English-specific scoring instrument and later restatements. An individual Liberpedia record should therefore pin the exact entry and files, recover the actual input and decoding rule, run its controls, and state only the bounded result. A ledger label alone must never be converted into “this method failed.” Existing Liberpedia records can be linked only after comparing their actual pages, symbols, parameters, and exclusions with the named entry.

Next source-review unit: screen the ledger's 48 negative entries for runnable, archived evidence; cluster equivalent sweeps before replay; start with entries whose inputs and positive controls are available. Record missing files explicitly. In parallel, inspect the other candidate repositories by stable revision and add their distinct methods to the same source-specific intake. No public-repository coverage percentage is warranted yet.

The [public-attempt inventory](public-attempt-inventory.json) now indexes all 172 entries from that exact ledger and links source files to candidate local records. A shared source filename is only a discovery hint: the [reconciliation notes](public-attempt-reconciliation.json) reject three false overlaps and identify the precise covered subclaims in reviewed entries. Neither file treats a source's negative label as an independently reproduced result or counts ledger entries as distinct solving ideas.

## A repository with a complete method inventory

[LiberPrimus/Failed-Attempts](https://github.com/LiberPrimus/Failed-Attempts/tree/d219a8099f8d24e52496e9ee3456ed9980893884) was inspected across all ten tracked files at the pinned revision. Its [inventory](failed-attempts-inventory.json) groups three methods: the 43-key Vigenère sweep, index/prime circumference substitutions, and a page-56 hash lookup requiring a particular JPEG set. The [Vigenère replay](../experiments/records/public-wordlist-vigenere/article.md) matches all 2,365 archived rune-bearing page/key prefixes. The [circumference replay](../experiments/records/public-circumference-substitutions/article.md) matches both public outputs and records that they use truncation despite the README's rounding instruction. The hash lookup remains source-input dependent. This is complete file and method intake for one repository, not evidence of complete public-repository coverage.

The first two replays are the related [R22-A self-embedded selections and R23-A2 printed-line acrostics](dukotah-r23-a2-source-audit-2026-10-22.md). Their commands reproduce the reported 3,508-selection and 48-read results, respectively, but the planted controls do not pass either experiment's final family threshold. They remain reported attempts, not independently established negatives.

The [R22-C literal-imperatives audit](dukotah-r22-c-scope-audit-2026-10-22.md) independently maps its 12,956 source runes to actual LP2 image pages: 00–55 except number-only 50, not the report's shorthand “0–54.” The public checkout lacks a generated language model and a required source corpus, so its 185-operation decoder verdict has not been replayed. A separate [four-phase IoC test](../experiments/records/four-phase-ioc/article.md) now checks the narrower fixed four-way concentration prediction with page-preserving controls and a planted positive case.

The [R22-D red-initial image audit](dukotah-red-initial-audit-2026-10-22.md) reproduced all 58 source red-pixel totals but found that two pages selected as “drop-caps” show only ordinary-sized red text. A component-based review identifies 13 pages with large initials, including pages with two initials or an initial below earlier content. This invalidates the source's published 15-page *feature list* as a catalogue of large initials. A [corrected page-presence order test](../experiments/records/red-initial-presence-order/article.md) now checks the 13-page spacing with exact run/span counts, seeded controls and planted patterns. Initial identities, within-page positions and the source's full five-statistic conclusion are not repaired by that narrower test. The [public illustrated guide](../articles/red-initials.html) gives the visual comparison and original page links.

An existence check against the pinned Git tree found all cited evidence paths for the 44 negative-labelled entries that name evidence; four name no evidence path. Thirty-one negative-labelled entries include a reproduction command. Three round-28 entries use filenames relative to their lane directories, and those files also exist after resolving that context. **File existence is only intake evidence:** it does not verify file contents, the reproducibility of a command, the stated controls or the negative conclusion. The two selection replays show why each of those checks matters.
