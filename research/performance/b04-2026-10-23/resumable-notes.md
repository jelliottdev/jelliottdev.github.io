# B04 A/B/C checkpoint runner

`resumable.py` wraps the pinned B04 `harness._work` unchanged. It freezes the ordered source seed bytes, exact A/B/C axes, source segments, decoder settings, and pinned source/data hashes in `manifest.json`. It splits only the seed list. Each completed chunk is written atomically and validated against its manifest and expected decode count before reuse. A changed manifest needs a new output directory. A changed chunk fails closed. A complete merge contains all decode counts, source score histogram, per-generator/reduction maxima, top rows, and the source `sweep.stage_summary` format needed for Stage D selection. In that summary, elapsed time and rate are null because a resumed, parallel run has no single source-style wall clock.

`test_resumable.py` exercises A, B, and C on a synthetic ciphertext with two seeds, including all 55 synthetic page segments for C. For each stage, one- and two-process checkpoint runs match the unchanged source harness exactly on rows, histogram, axis maxima, counts, and stage summary. It also interrupts A after one chunk, resumes without rewriting that chunk, and rejects a corrupted chunk. These tests do **not** search the manuscript. Full execution additionally requires `--allow-full` and a pinned G1/G2 passing receipt; the existing G1/full-message preflight alone does not certify G2.

`--g2-plant` runs the separate source `control.py` planted ranking gate over the **complete** Stage-A dictionary and settings; it reads no LP2 ciphertext. Its 120-rune plant is derived from `control.PLAIN`, which differs from the fallback plant in source `sweep.py`. The historical `results_gates.json` therefore is not a byte-identical target receipt for this run. The wrapper hashes the exact plant ciphertext, control source, and ordered 2,165-entry dictionary. A completed G2 run can be checked with `verify_g2.py`; a combined gate receipt binds the passing G1 preflight and fresh G2 rank to those hashes before a manuscript sweep is permitted.

The source uses `Pool.imap_unordered`, a score-only top-K replacement test, and score-only final sorting. If equal scores straddle the top-K cutoff, retained row identities can depend on worker completion order. This wrapper merges chunks in seed order for repeatability, but that may choose different tied rows from a prior source run. Histograms, counts, and maximum scores remain exact. Such a tie can also alter which exact tuples Stage D selects, so Stage D must use this run's frozen A/B/C summary, not a mixed archive. The synthetic parity fixture did not encounter a cutoff tie.

The wrapper deliberately leaves source `skipdecode.beam_decode` zero-extension of short keys unchanged. That behavior still needs a separate candidate-path audit; a passing control does not license silently changing the historical method.

The pinned source stage sizes are A **1,385,600**, B **1,290,240**, C **3,548,160**, totaling **6,224,000** candidate decodes. These are settings, not separate ideas. The archived Stage D reports **150** page decodes in 6.3 seconds and **150** whole-stream decodes in 10,192.1 seconds (about 2 hours 50 minutes) on its original host: 300 Stage-D decodes in total. This is a planning estimate, not a new timing measurement; current synthetic beam benchmarks vary by key and text length. Stage D is not part of the checkpoint wrapper and must follow a completed A/B/C merge with the same manifest.
