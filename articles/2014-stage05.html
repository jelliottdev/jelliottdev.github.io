The four-page first koan, LP1-06 through LP1-09, can be recovered from a preserved response to the historical fourth onion service. The later capture is a hexadecimal rendering of a gzip file. Once decompressed, it contains two JPEGs in forward byte order and two more in the reversed remainder. All four recovered files match the original manuscript images hosted here byte for byte.

This follows the preceding archived captures, which supplied LP1-03 through LP1-05. The source-to-page route and the reading of the koan are separate checks.

The koan’s next archived branch contains signed audio, number squares and a book code before the following manuscript pages appeared.

What the archive kept

The first saved page has an HTML comment <!--3301--> followed by a hexadecimal body of 256 decoded bytes. The later saved response consists of hexadecimal lines that decode to 2,532,309 bytes. Its first two bytes are 1f 8b, the gzip signature. Decompression gives a 3,010,703-byte stream.

The archive records these as two captures from different points in the historical service. The short body is not used to create the four pages, and the captures alone do not explain when the service changed.

How the four images are split

Starting at the beginning of the decompressed stream, take the first complete JPEG ending at ff d9: 823,807 bytes, exactly LP1-06. The next complete JPEG is 823,514 bytes, exactly LP1-07. Reverse all remaining bytes. In that reversed remainder, the next complete JPEG is 638,805 bytes, exactly LP1-08; the final 724,577 bytes form LP1-09. Their lengths add to the full decompressed stream, leaving no unexplained bytes.

Download and verify

The reference-data bundle includes the raw captures, the replay script, the output report, and the source manifest. Extract it alongside original-images.zip in the same folder, then run python scripts/replay_2014_stage05.py --check from that folder. The script decodes and splits the stream and compares each result to the hosted original. Add --extract-dir recovered-pages to save copies without overwriting files.

The hosted capture is pinned to an archive revision; its historical notes describe the same split. Matching the JPEGs establishes the path from these particular saved bytes to the four pages. It does not verify any claimed live-service timing or explain the separate OutGuess layer in LP1-08.
