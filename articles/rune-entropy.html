Single-rune entropy summarizes a frequency distribution. It is low when most observations belong to a few symbols and higher when observations are spread more evenly. It does not inspect the order of the runes. Use it beside IoC as a descriptive measurement, not as a test that a page is encrypted or random.

From counts to bits

Let N be the number of retained runes and c be one rune’s count. Its empirical probability is p = c/N. Compute H = −sum(p × log2(p)) over nonzero counts. A zero count contributes zero; do not attempt to evaluate log2(0). Base-two logarithms give bits per symbol. This is the Shannon-entropy formula applied to observed frequencies; SciPy’s entropy reference documents the formula and logarithm-base convention. The script here uses Python’s standard library.

For two equally frequent symbols, each contributes −0.5 × log2(0.5) = 0.5; their total is 1. Notice that grouping and alternating the same four A and four B symbols changes nothing. Neither does consistently renaming A and B. The statistic summarizes the counts, not the arrangement.

An empty rune stream receives null, because there are no empirical probabilities to calculate; it should not be mistaken for a nonempty one-symbol stream with entropy zero.

The most even counts this length permits

For 269 runes in a 29-rune alphabet, divide 269 = 29 × 9 + 8. The most even possible counts are eight symbols appearing ten times and twenty-one appearing nine times. Their entropy is 4.856331980164111 bits per rune. The report includes this as finite_sample_maximum_entropy_bits.

In general, write N = Kq + r, where K is the alphabet size and r is the remainder. Assign count q + 1 to r symbols and q to the other K − r symbols, then apply the entropy formula. Moving one observation from a count that exceeds another by at least two makes the counts more balanced and increases entropy; repeating this gives the maximum. This is a bound across all possible count vectors of that length, not a rearrangement of the page’s actual counts.

Why random samples need not reach the maximum

Imagine a source that independently emits A or B with equal probability. Its underlying distribution has entropy 1 bit. Now take just two symbols. There are four equally likely ordered samples:

SampleObserved countsEmpirical entropy
AA2, 00 bits
AB1, 11 bit
BA1, 11 bit
BB0, 20 bits

The average measured entropy is (0 + 1 + 1 + 0) / 4 = 0.5 bits. That is below both the source’s entropy and the maximum empirical entropy attainable with two symbols. Yet every sample was produced by the same independent, balanced source. No measurement error or hidden pattern was needed to create the gap.

The distinction is between a source distribution and the frequencies in one finite sample. With only two draws, a symbol can be missing simply because it did not occur. The empirical formula assigns that unobserved symbol probability zero even though its probability under the stipulated source remains one half.

Enumerate the example

from itertools import product
from collections import Counter
from math import log2

values = []
for sample in product("AB", repeat=2):
    counts = Counter(sample).values()
    h = sum(-(c / 2) * log2(c / 2) for c in counts)
    values.append(h)
    print("".join(sample), f"{h:.1f}")
print("Mean:", sum(values) / len(values))

The final line is Mean: 0.5. This exact enumeration assumes equal probabilities for all four samples. A model that fixes the counts at one A and one B permits only AB and BA, both with entropy 1. Those are different models: random sampling allows the counts to change, while shuffling a fixed page does not.

For manuscript comparisons, preserve the sample length, alphabet, and proposed sampling rule. The toy example explains the distinction; it does not assign a probability to LP2-31’s entropy or establish that its runes were generated independently. See null models and selection before treating a shortfall from the maximum as evidence about a cipher.

Can two texts have the same IoC but different entropy?

Yes. Both measurements use symbol frequencies, but they compress those frequencies in different ways. IoC counts matching pairs; entropy uses logarithms of the observed proportions. One score does not generally determine the other.

Compare these two invented six-symbol strings. They are teaching examples, not manuscript readings. Their lengths and matching-pair totals are identical:

InputCountsIoCEntropy
AAABBB3, 32/51 bit
AAAABC4, 1, 12/5About 1.251629 bits

The matching-pair totals are 3 × 2 + 3 × 2 = 12 and 4 × 3 + 1 × 0 + 1 × 0 = 12. Each string has 6 × 5 = 30 ordered pairs of distinct positions, so both IoCs are 12/30 = 2/5.

The second string contains a more dominant symbol, but also two less frequent alternatives instead of one. Its entropy is higher, while IoC ties. Sorting pages by entropy therefore need not produce the reverse of their IoC ranking. Higher entropy here does not establish a better decryption, more meaningful text or a more secure cipher.

Check the comparison

Run this self-contained Python example. It calculates IoC as an exact fraction and entropy with base-two logarithms:

from collections import Counter
from fractions import Fraction
from math import log2

for text in ("AAABBB", "AAAABC"):
    counts = Counter(text).values()
    n = len(text)
    ioc = Fraction(sum(c * (c - 1) for c in counts), n * (n - 1))
    entropy = -sum((c / n) * log2(c / n) for c in counts)
    print(text, "IoC:", ioc, "entropy:", f"{entropy:.6f}")

Expected output:

AAABBB IoC: 2/5 entropy: 1.000000
AAAABC IoC: 2/5 entropy: 1.251629

Adding the 26 or 27 unused runes to the count array changes neither result: zero counts contribute nothing. Both examples therefore fit within the same 29-symbol alphabet. Their order can be rearranged without changing either score. Matching symbols: with or without replacement?

Choose one position uniformly from a text of N symbols, then choose a second position. If the second choice can select the first position again, the probability of a matching symbol is C = sum((c/N)²). This is sampling with replacement. If the positions must be different, the matching probability is the IoC used in this wiki: I = sum(c(c−1)) / (N(N−1)).

The difference is the possibility of selecting the same position twice, which always produces a match. For N greater than one:

Separate the squared counts
sum(c²) = sum(c(c−1)) + N
Divide by N²
C = 1/N + ((N−1)/N) × I
Recover IoC
I = (N × C − 1) / (N−1)

For AAABBB, C is 1/2 but IoC is 2/5. If all N symbols are different, IoC is zero while C is 1/N: the only matching draws with replacement are those that revisit the same position. A one-symbol text has C = 1, but its IoC is undefined because there is no pair of distinct positions.

A lower bound on Shannon entropy

The same empirical probabilities give a useful mathematical check: H ≥ −log2(C). To see why, select a symbol using its observed probability p. Shannon entropy is the average of −log2(p); the average of p under that selection is sum(p²) = C. The function −log2 is convex, so its average cannot be below its value at the average. Equality holds when all observed symbols have equal probabilities.

This is a bound, not a conversion formula for entropy. The two six-symbol examples above have the same C = 1/2 and therefore the same bound of 1 bit, but their entropies differ. Do not insert IoC directly into the logarithm: it uses a different sampling rule and can be zero even for a nonempty text.

from fractions import Fraction

n = 269

print("With replacement:", collision)

What it cannot distinguish

A pure transposition preserves every count, so it preserves this entropy. A fixed one-to-one substitution relabels the same counts and also preserves it. Therefore this score cannot choose among those transformations of the same input. See cipher invariants.

This is not an entropy-rate estimate: it does not model how a symbol depends on preceding symbols. The alternating example above has a predictable pattern despite its balanced counts. Use repeated sequences to inspect adjacency, and specify a comparison model before claiming statistical surprise. A frequency summary alone does not measure meaning, compressibility under a particular compressor, or resistance to cryptanalysis.
