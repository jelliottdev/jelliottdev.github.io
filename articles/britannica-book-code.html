The archived 2012 Britannica clue can be replayed against a preserved Project Gutenberg text of the Cicada article. Nineteen line-and-character coordinates and three literal prime instructions produce eq6emgv2eHsrix6t.onion. This is a reproduction of a historical book-code interpretation, not a new Liber Primus reading.

The two inputs

The preserved signed clue begins “In twenty-nine volumes, knowledge was once contained.” The public ClevCode account records that clue and discusses Britannica as a candidate, but its account of this branch stops before the extraction reproduced here. It is evidence for the historical clue, not a source for claiming that this particular replay was completed there.

The text input is Gutenberg ebook 31447, Encyclopaedia Britannica, 11th Edition, “Chitral” to “Cincinnati”, volume 6, slice 3. The catalogue credits Marius Masi, Don Kretz, Juliet Sutherland and the Online Distributed Proofreading Team. Use the preserved Latin-1 text file, whose SHA-256 is recorded in the replay ledger. An HTML rendering, reflowed ebook or different text revision need not preserve the required positions.

Why the pause points to edition 11

The original 2012 image supplied 76 line-and-character coordinates for the Mabinogion posts. The timestamped post replay shows a 22-hour-51-minute gap between lines 65 and 66 under the named-account rule. When posting paused at line 65, rows 66 through 76 of the coordinate list still could not be read: 11 rows remained. The later signed clue asks for that count, after mentioning 29 volumes of knowledge. Read together, those details direct solvers to the 29-volume Encyclopaedia Britannica, 11th edition. The next phrase, “my first name,” supports looking up Cicada.

This is a reconstruction of the clue’s arithmetic, not a claim that the subreddit stopped at line 65. Posting resumed and continued beyond the 76 rows needed for the first book code. The post-order guide documents that continuation and the limits of what can be inferred from the preserved snapshot.

Count physical lines and characters

  1. Find the unique heading beginning CICADA (_Cicadidae_). Treat that physical line as line zero.
  2. The following line, beginning Hemiptera, generally, is line one. Keep the file's physical line wrapping; do not rewrap the paragraph to fit the screen.
  3. For row:column, select the numbered line, then count characters from one. Spaces, punctuation and underscore markup count. Preserve case.
  4. Replace each instruction for the product of the first two primes with 6, and the instruction for the first prime with 2. Read all outputs in their given order.

For example, 1:29 selects e from the first numbered line. The later 1:1 selects its capital H. That explains why the raw extraction contains an uppercase character; silently lowercasing it would conceal part of the actual procedure.

The ledger includes the source line and zero-based character index for every coordinate, so the extraction can be inspected character by character. It also records four numbering combinations: counting or skipping the heading, and zero- or one-based character positions. Only the stated combination gives the recorded output. Two alternatives encounter an out-of-range column, explicitly marked ?; that marker is not a source character. These four comparisons do not exhaust all conceivable text-processing conventions.

The clue's signature

A fresh offline GnuPG check in an isolated temporary keyring verifies the preserved clue under fingerprint 6D854CD7933322A601C3286D181F01E57A35090F. The verification record contains the input hashes and machine-readable status. The historical message uses SHA-1, so the verification command explicitly enables compatibility for that digest; it does not change the user's normal GnuPG configuration.

A valid signature binds these message bytes to the corresponding key. It does not independently establish a civil identity, signing time, Gutenberg file version or correctness of a proposed solution. The signature guide explains that distinction.

Reproduce the extraction

Extract the reference-data bundle with folders intact, or use the repository. The extraction requires only Python 3. Signature verification additionally requires GnuPG on your command path.

python scripts/reproduce_britannica.py --check
python scripts/reproduce_britannica.py --verify-signature

The first command recomputes all outputs and numbering comparisons. The second imports only the bundled public key into a temporary keyring and checks the preserved signature without fetching keys. It prints the verified fingerprint and hashes. Download the script; a script downloaded alone still needs the files named above.

What this adds to Liberpedia

This provides a concrete historical example of a book code whose reproducibility depends on an exact text representation. The three printed “widsom” occurrences are a separate source lead in different articles. The historical extraction does not show that LP copied that spelling, used Britannica as a key, or refers to those articles.

This replay reconstructs the Mabinogion pause count from archived post timestamps and the 76 original coordinates. It does not establish byte identity between the preserved Gutenberg text and a file downloaded in 2012. The source-file hashes make the present extraction exact without filling that historical gap by assumption.
