A null-removal hypothesis treats some ciphertext symbols as material that should not appear in the recovered message. The proposed nulls might be a particular rune, positions selected by a pattern, or padding added to fill a block. This is different from an interruption that preserves a rune while pausing the key. Calling both operations “skip” conceals a consequential choice.

Deleting positions creates a search

If exactly d of n positions may be removed, there are n! / (d! × (n − d)!) position subsets. If each position can independently stay or go, there are 2n subsets, including the empty retained stream. These count choices, not necessarily distinct outputs.

For example, delete exactly one position from the invented input 0, 0, 1, 2. Positions are zero-based.

There are four deletion choices but only three retained sequences. Preserve the deleted-position list even when values coincide: the source-position trace differs, and later operations that use original positions can distinguish those choices.

Deletion keeps the surviving symbols in order

Removing positions without any other transformation can only produce a subsequence: choose some original positions in increasing order and retain their values. It cannot exchange the surviving symbols or invent a new value. This gives a quick necessary-and-sufficient check for a literal target under unrestricted deletion.

Original streamDesired retained streamPossible by deletion alone?
0, 1, 0, 2, 10, 2, 1Yes. Retain positions 0, 3, 4 or 2, 3, 4.
0, 1, 0, 2, 12, 0No. No 0 occurs after the only 2.
0, 1, 0, 2, 10, 3No. The input contains no 3.

To check existence, scan the input from left to right, taking the earliest available match for each successive target symbol. If the target is exhausted, it is a subsequence. Taking an earlier match leaves at least as much remaining input as taking a later one, so this greedy check does not need to enumerate every deletion subset.

The existence check does not count every position trace, prove the positions are nulls, or establish that the target was independently predicted. In the first example, the two successful traces are two ways to obtain one output, not two independent confirmations. With a maximum deletion allowance d, a target of length m from an input of length n also requires n − m ≤ d.

These statements apply to deletion alone on the compared symbol stream. If deletion changes key alignment before decoding, the decoded values can change as well, and this simple subsequence test does not describe the whole pipeline. If a fixed decoding is completed first and then its output is filtered, compare the target with that full decoded output.

Define deletion relative to the cipher

Removing a symbol before decoding can shift every later key assignment. Decoding first and then removing its output consumes that symbol’s key position. Neither operation is equivalent to copying the symbol and pausing the key. The worked skip comparison shows these effects on the same input.

Declare whether retained symbols keep their original indices or receive new consecutive indices, whether deleted symbols update feedback state, and how word boundaries are preserved. Also state whether the rule acts on rune symbols, transliteration characters or raw bytes. Deleting one character from a multi-letter rune label is not deleting one rune.

Require evidence beyond an improved fragment

Freeze the deletion rule and its maximum deletion count before selecting a reading. Apply it to an untouched continuation with the same boundary and state rules. Report the fraction removed, all competing candidates and any changes to word lengths or repeated patterns. A score that rewards a short readable fragment may favor deleting most of the input; the acceptance rule must account for retained length.

Controls should repeat the same deletion search and scoring. Comparing a heavily selected retained fragment with an unselected full-length random stream asks a different question. If the null positions come from independent image evidence, record how they were measured before examining the decoded text.

What has been tested here?

The single-rune deletion census exhausts one narrow class: remove every occurrence of one fixed rune type and recount LP2's raw adjacent equal pairs. All 29 variants raise that count from 86 to 92–109. This is a ciphertext measurement, not a plaintext recovery or a test of selected-position deletion. The decoder-skip controls test different key-advancement behavior. Likewise, copying an F rune in a known reading is not evidence that every F on an unsolved page is disposable.
