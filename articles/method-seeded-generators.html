A seeded generator expands a starting value into a sequence. A cipher can use that sequence as shifts, bytes or route choices. To test this idea, specify both the generator and the conversion from its output to the decoding operation. A long generated stream is not the same hypothesis as an independently chosen key value at every position.

A complete toy generator

This deliberately small recurrence illustrates the required details; it is not a secure generator or a proposed Liber Primus solution. Start with state 4. Before each output, update state = (5 × state + 3) mod 29, then emit the new state as the shift. Subtract it from the ciphertext index modulo 29.

Emitting the initial state before updating would start with 4 instead of 23 and give a different decoding. An instruction to use the same formula and seed would therefore still be incomplete without the timing convention.

Reproduce the example

This Python example uses only the standard language. It checks the full decoded sequence; it performs no search on manuscript text.

ciphertext = [23, 3, 15, 13, 28]
state = 4
decoded = []
for position, value in enumerate(ciphertext):
    before = state
    state = (5 * state + 3) % 29
    plain = (value - state) % 29
    decoded.append(plain)
    print(position, before, state, value, plain)
assert decoded == [0, 1, 2, 3, 4]

What a real proposal must fix

Record the exact generator, seed encoding and allowed seed range. For a byte-oriented generator, specify character encoding, byte order, counter format and how outputs become rune indices. State whether an output is consumed before the first rune, how punctuation is treated, and where the stream restarts. A password, decimal number and its binary integer representation are different seed inputs unless the implementation explicitly equates them.

Output conversion can change the distribution. For example, reducing a uniform byte modulo 29 gives residues 0–23 nine preimages each and residues 24–28 eight each, because 256 = 8 × 29 + 24. Rejecting byte values 232–255 before reduction gives each residue eight preimages, but consumes a variable number of bytes. Those are different algorithms and can lose alignment with each other.

Seed bounds are not output-length bounds

A fixed generator with b seed bits produces at most 2b streams of a chosen length. Distinct seeds may collide. Trying multiple generators, seed encodings, offsets and output conversions expands the search beyond the seed count. Record every tried setting and deduplicate identical outputs.

The toy example has only 29 allowed seeds if its starting state is restricted to 0–28. Allowing arbitrary integers does not add streams here: reducing the seed modulo 29 gives the same subsequent states. This is a property of this recurrence, not a general statement about generators.

A matching prefix can leave several seeds

Change the toy generator's output rule to emit state mod 3 after each update, while keeping its internal state modulo 29. This intentionally discards information: the visible output is now only 0, 1 or 2. It is a separate toy generator, not the one used in the first decoding example.

Starting from seed 4 produces 2, 2, 1, 1, 0, 1. Exhaustively comparing seeds 0–28 gives:

Observed output prefixMatching seedsCount
21, 4, 8, 12, 15, 19, 22, 23, 269

2, 2, 1, 141

The first three values do not identify the seed in this declared domain. The fourth distinguishes the two remaining candidates. If the fourth value was already part of the supplied crib, this is still fitting the crib; an independent continuation must come from material not used to choose the seed or rule.

def outputs(seed, count):
    result = []
    for _ in range(count):
        seed = (5 * seed + 3) % 29
        result.append(seed % 3)
    return result

target = outputs(4, 4)
for length in range(1, 5):
    matches = [seed for seed in range(29)
               if outputs(seed, length) == target[:length]]
    print(length, matches)

Seed recovery is conditional on the generator

The unique match in the last row means one seed among 0–28 for this exact recurrence, update timing and output conversion. It does not identify the recurrence among all generators. Another generator or a table containing the target sequence could emit the same prefix.

Even here, allowing arbitrary integer seeds would give seed 4 infinitely many equivalent labels: 4, 33, 62 and so on reduce to the same starting residue. Report uniqueness among canonical states or within the declared seed range, rather than claiming that only one integer can work.

For a fixed model and nested exact prefixes, the survivor set can only shrink or stay the same as observations are added. If a supposedly identical search gains candidates after adding a prefix symbol, inspect whether the bounds, alignment, mismatch allowance or comparison changed. This monotonicity does not hold for arbitrary top-ranked lists under a changing score.

Existing test and its limits

The known-crib seed experiment tests two specified hash generators and 4,096 seeds each on synthetic ciphertexts. It includes missing-seed, wrong-generator and incorrect-crib controls, and checks a continuation beyond the fitted opening. It does not search the toy recurrence above or identify an LP generator.

A failed seed search excludes only its tested settings under its acceptance criterion. A short matching opening can leave several seeds; an untouched continuation is needed to distinguish them. Conversely, obtaining a desired reading by choosing an unrestricted key after the fact says nothing about whether a generator produced it. See unrestricted keys and one-time-pad claims.
