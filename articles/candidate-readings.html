A script can generate thousands of candidate readings without telling us whether any is a decryption. To interpret its result, first ask what the script was instructed to recognize. Matching a fixed beginning, receiving a high language score and reproducing a complete reading are different achievements.

What an opening test answers

Several experiments in this wiki compare the first twelve output rune indices with nine beginnings taken from known readings. The numerical-sequence family, for example, uses Warning, Welcome, Some Wisdom, the first koan, Loss of Divinity, the second koan, Instruction, LP2-56 and LP2-57. These are exact vectors stored in each plan, with hashes identifying their source traces.

This asks a useful, limited question: does this declared transformation produce one of those particular beginnings at the start of this input? It does not ask whether the output contains any possible English sentence. There is no established requirement that an unsolved page must repeat a known opening.

The comparison is in runes, not twelve Latin characters. A rune label such as TH can contain more than one letter. See rune counts and character counts before attempting to reproduce the comparison from a displayed transliteration.

A match can be too narrow for the conclusion

The following invented examples use ordinary characters so the distinction is visible. Suppose the test accepts any string beginning with THE , while the complete reference is THE DOOR IS OPEN. None of these strings is a manuscript result.

CandidateOpening testWhat remains unknown
THE DOOR IS OPENPassesThis also equals the supplied full reference, but that requires a separate comparison.
THE XXXX XX XXXXPassesThe opening test says nothing about the remainder.
PLEASE OPEN THE DOORFailsThe readable sentence begins differently. This test was not designed to recognize it.

The second row is a correct positive result for the stated prefix test. The error would be reporting it as a complete decryption. Likewise, the third row is a correct negative for that prefix; the error would be treating it as proof that the text cannot be readable.

Read the actual result with its scope

Prime-minus-one shifts
3190 configurations on 55 nonempty LP2 pages produced no matches to the nine declared beginnings. The tested offsets, directions and uninterrupted advancement are part of that result.
Fibonacci shifts
3190 configurations produced 1540 distinct full page outputs. The repeated configurations do not add different candidates; neither count is a count of independent statistical observations.
Row and column reading routes
Sixteen declared routes per nonempty page produced no matches to the same nine beginnings. This does not cover arbitrary transpositions or a second cipher applied after rearrangement.

A precise report says “no declared opening matched under these rules.” It should not shorten this to “Fibonacci does not work” or “transposition was ruled out.” Conversely, keeping a method open is not evidence in its favor: it identifies what the recorded test has not settled.

What a broader language test would need

A language score could rank candidates that begin differently. To make that ranking reproducible, a new experiment would need to publish the scoring rule as carefully as the cipher operation. It should specify:

  1. The representation. Decide whether the model scores rune indices, literal rune labels or interpreted English. Specify how spaces, punctuation and multi-letter labels are handled. Do not silently repair spelling before scoring.
  2. The reference material. Identify the corpus, its version and hash, and the exact conversion into the scored alphabet. Separate material used to build or tune the score from material reserved to check its behavior.
  3. The rule. Publish the formula or executable model, treatment of unseen sequences, length normalization and any acceptance threshold. “Looks like English” is not a reproducible numeric criterion.
  4. The search. Record all keys, offsets, page subsets and score variants examined. A favorable score selected from many candidates needs a comparison that includes that selection process; see chance comparisons.
  5. The controls. Show whether known readings score sensibly, and what happens to appropriate altered or shuffled inputs. A reading used to choose the score cannot also serve as untouched evidence that the chosen score generalizes.

The highest-scoring candidate always exists when a finite nonempty set has numeric scores. Its rank alone does not tell us that the candidate is meaningful. Publish the competing outputs and score differences, rather than showing only the winner.

These requirements describe a possible follow-up, not a language-ranking experiment already completed by the records linked above. The fixed-opening searches retain their original acceptance rule and results.

If a candidate looks promising

Save the complete output and the exact settings before making interpretive changes. Check the transcription against the image, then apply the same declared rule to the rest of the stated input. Mark every exception, skipped rune and inserted word. A short attractive phrase should not hide unexplained text elsewhere.

Distinguish a control from a prediction. Recovering a known reading can show that an implementation handles a documented method. If you designed a rule around that reading, recovering it does not independently establish the rule on an unsolved page. A useful follow-up specifies what additional text or feature the rule should explain before inspecting that result.

When changing a criterion or boundary rule after seeing an output, preserve the original record and describe the change in a related experiment. The reproducibility guide explains how to retain the inputs, commands and limits. Have we tried it? keeps those separate records together as a family without turning a narrow negative result into a universal verdict.
