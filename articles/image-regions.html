An image region specifies where a measurement was made. Keeping the rectangle, original image, and measurement rule together lets another person inspect the same pixels.

Reading a rectangle

The wiki uses [x, y, width, height] in original-image pixels. The origin is the top-left; x increases rightward and y downward. For [599, 664, 153, 501], the region starts at x = 599, y = 664 and covers 153 columns and 501 rows. In a half-open crop convention, the right and bottom bounds are 752 and 1165.

A thumbnail or resized preview uses different display coordinates. Use the original JPEG or the wiki’s region inspector rather than copying screen coordinates into a dataset.

Connected components

A connected component is a group of selected pixels joined by the chosen neighborhood rule. Eight-connectivity includes horizontal, vertical, and diagonal neighbors. Four-connectivity excludes diagonal neighbors; the same image can produce different counts under those definitions.

The published opening-page measurement uses foreground grayscale below 140 and retains eight-connected groups containing at least 20 pixels. Tiny isolated specks are excluded by that area threshold. A count of 13 means thirteen qualifying groups under this rule, not necessarily thirteen intentional dots.

Connectivity is transitive: the two outer pixels need not touch each other to belong to the same group. A path through the middle pixel is enough. This is why a thin diagonal bridge can merge what a person sees as separate marks.

Reproduce the small mask

This Python 3 example counts all selected pixels, with no minimum-area filter. It needs no image package:

def component_areas(points, diagonal=False):
    remaining = set(points)
    neighbors = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    if diagonal:
        neighbors += [(1, 1), (1, -1), (-1, 1), (-1, -1)]
    areas = []
    while remaining:
        pending = [remaining.pop()]
        area = 0
        while pending:
            x, y = pending.pop()
            area += 1
            for dx, dy in neighbors:
                neighbor = (x + dx, y + dy)
                if neighbor in remaining:
                    remaining.remove(neighbor)
                    pending.append(neighbor)
        areas.append(area)
    return sorted(areas)

pixels = {(0, 0), (1, 1), (2, 2)}
assert component_areas(pixels) == [1, 1, 1]
assert component_areas(pixels, diagonal=True) == [3]
assert component_areas(set()) == []
print("Four-connected:", component_areas(pixels))
print("Eight-connected:", component_areas(pixels, diagonal=True))

Each selected pixel is removed from the remaining set when it is assigned to a component, so it cannot be counted twice. The reported areas total three under either rule. Connectivity changes grouping, not how many foreground pixels exist.

The real opening-page rule additionally discards components smaller than 20 pixels. Applied to this tiny teaching mask, that filter would retain zero components under either connectivity rule. Always report the neighborhood, brightness threshold and minimum area together; “three dots” is not a complete measurement specification.

Color classification

Within a stored rectangle, foreground pixels use the weighted brightness test 0.299R + 0.587G + 0.114B < 140. A foreground pixel is red-dominant when R − max(G,B) > 70. A red-dominant fraction above 90% gives “red”; below 10% gives “dark”; intermediate cases are “mixed/uncertain.” These labels summarize pixels under a rule, not a chemical analysis of ink.

What a successful recount establishes

Matching a recorded count confirms that the stated operation reproduces it on the stored rectangle and exact image bytes. It does not prove that the rectangle includes every relevant mark or that two overlapping rectangles should be interpreted as one character. Segmentation, symbol identification, and cipher interpretation are separate decisions.
