Start with the question you want a measurement to answer. A symbol count, a repeated sequence and an image-region count describe different features of the manuscript. This index points to the relevant guide, its inputs and its reproduction instructions.

Choose a measurement

Does random-looking text imply a one-time pad?
Work through a finite example where each ciphertext symbol is uniform but the pair leaks a plaintext relationship. Distinguish independent keys, short seeds and the limits of a failed search.
How unusual are the word lengths in the historical corpus?
Inspect all 25,565 eligible file prefixes, exact ties and the effect of counting identical files once. The complete comparison includes every selected measure; its ranks describe this corpus and do not identify a language.
Could the plaintext be another language?
Compare the same passages in eight languages under explicit boundary and symbol-unit assumptions. Inspect full distributions, shorter aligned blocks, and controls using the established LP readings.
Does a spectrum label identify a hidden number?
A synthetic tone demonstrates why an FFT bin can read 1033.59375 Hz without the signal containing that exact frequency. Reproduce the calculation and compare zero-padding with a longer recording.
Why are there so few equal neighboring runes?
Locate all 86 doublets, inspect the three 4–2–1 groups, and separate count observations from proposed autokey explanations.
How long are the rune words?
Inspect token boundaries, compare rune-only and number-inclusive counts, and see what a comparison with an English corpus still needs.
Do runes match at a particular distance?
Count equal pairs at each lag, retaining the changing denominator and a stated shuffle expectation. A peak alone does not establish a key length.
How evenly are symbol frequencies distributed?
Calculate single-rune entropy in bits. The guide contrasts frequency balance with sequence order and randomness claims.
How unevenly are runes distributed?
Inspect per-rune frequencies and whole-page IoC. The guide supplies a baseline for the archived pages, a frequency chart and worked pair-count calculations.
Which rune sequences repeat, and where?
Count overlapping bigrams, trigrams or other window lengths. Reports include rune ordinals, source-file locations and the exact original slices.
Does a word or sentence have a prime or emirp sum?
Sum the declared rune values, reproduce known-reading examples, and compare explicit alternative encodings. Boundaries and text layers are part of the calculation.
How were dots, regions or colors counted?
Inspect original-image rectangles, pixel thresholds and connected-component rules. The opening-page inventory provides a scoped example with a reproduction script.
Do rows, columns and diagonals have equal totals?
Reproduce the documented square and compare it with other numerical arrangements. A symmetric grid need not be a magic square.
Which letter-and-number entries repeat?
Count exact, case-sensitive tokens on LP2-49–51. Download all 256 entries with grid coordinates and a frequency inventory; no numeral base is assumed.
Where does a word or phrase occur in the known readings?
Search contextual sections, or locate literal decoded wording on an exact page across line breaks. Reports distinguish word, character, and literal-line positions from rune offsets. Unsolved ciphertext is not searched as unknown English.

For completed records, the experiment reading guide distinguishes arithmetic audits, statistical comparisons, bounded cipher searches and tool checks, with examples of what each result establishes.

Understand your result

Keep the output beside the exact command that produced it. Then choose the question that matches what surprised you:

Two pages have the same IoC but different entropy. Is that an error?
Not necessarily. The worked six-symbol examples have equal matching-pair totals but different entropies. These scores summarize the same counts in different ways.
Why does a squared-frequency calculation disagree with IoC?
Check whether the calculation allows the same position to be selected twice. The pair-grid diagram shows which cells IoC excludes and how to convert between the two rates.
Entropy is below the uniform maximum. Does that show a pattern?
A finite random sample can have uneven counts. The two-symbol example distinguishes the source's entropy, the measured value, and the largest value the sample length permits.
I rearranged the runes, but the score did not change. Why?
Whole-stream IoC and single-rune entropy ignore order. A pure rearrangement preserves their inputs; it cannot improve either score. An order-sensitive measurement answers a different question.
There is a peak at one distance. Is that the key length?
The lag report counts matches and keeps each denominator. Interpreting the largest peak also requires a comparison model that accounts for all distances searched; see chance comparisons and selection.

None of these answers replaces checking the transcription. If the rune count itself differs, return to input layers and boundaries before comparing statistics.

Language comparison: choose the right control

A language ranking needs more than a list of scores. These four records answer different questions and share one experiment family:

  1. Aligned language profiles: compare the same FLORES passages in eight languages. Word-length similarity and fixed-substitution repetition statistics have different assumptions.
  2. Shorter aligned passages: check whether the ranking persists across eight disjoint sentence blocks, and whether known corpus languages match their corresponding reference profiles.
  3. Known LP readings: check transfer to actual manuscript style and spelling. The pool ranks closest to English, but some individual known-English sections rank other language profiles first. The record also shows how an embedded hash can distort an unfiltered word count.
  4. Exactly 2,896 tokens per sample: control the reference sample size. All complete reference samples are nearest to their own language profile, but the manuscript is farther from every profile than any of that language’s observed control samples. The reference ranges are descriptive, not confidence limits or rejection thresholds. Unlike the aligned-passage control, equal-token blocks do not cover identical translated passages.

Start with the baseline for the overall question, then use the controls to judge its limits. A nearest language is not a decryption or a probability that the plaintext uses that language. Each record provides its own scripts, exact inputs and download.

Why length and repetition can disagree

Consider the four-symbol example AAAA. Replacing every A with B gives BBBB. Applying successive shifts of 0, 1, 2 and 3 instead gives ABCD. Both transformations preserve the length, but only the fixed replacement preserves which positions match.

SequenceLengthMatching position pairsEqual neighbors
AAAA — input46 of 63 of 3
BBBB — fixed replacement46 of 63 of 3
ABCD — successive shifts40 of 60 of 3

The matching-pair fraction is the index of coincidence. This toy example explains why a length comparison can remain relevant under a changing substitution even when the language's original IoC and doublet rate do not. Length still needs its own assumptions: preserved word boundaries and one counted plaintext unit per rune. Adding nulls or representing several letters with one symbol can change it too.

What would a first-place language mean?

It means that this profile has the smallest measured distance among the profiles supplied. There will be a first-place result even if every candidate is a poor match. Adding another language, changing the genre, or changing how letters become rune units can change the ordering. The eight-language comparison therefore does not rank every possible plaintext language.

A concrete example comes from the equal-token control. The manuscript’s letter-length distance to the English development profile is 0.0831, compared with a largest observed English control distance of 0.0508. English wins the relative comparison while still lying beyond that observed reference range. This does not reject English: genre, spelling and the correspondence between letters and runes remain uncontrolled. It shows why a ranking and an absolute fit assessment are different questions.

Use the full distributions to see where even the nearest profile disagrees, then check the known-English manuscript controls. Some short sections rank another profile first. A useful next test must state what it adds: a new fixed corpus, a different encoding assumption, or a previously untouched section. Choosing whichever spelling or grouping improves a score after seeing it creates a new hypothesis; it does not independently confirm the earlier one.

Check the method before trusting its answer

A failed search can have several causes: the intended answer may be outside the tested keys, the decoder may not represent its alignment, or the scoring rule may reject meaningful text. These controls isolate different parts of that process. Choose the question that matches your method:

Would this score recognize meaningful text?
Give the scorer known text before asking it to recognize an unknown answer. The eight-language control measures fixed-threshold acceptance alongside letter shuffles. It tests the score, not a decoder or the manuscript’s language.
Can this decoder recover what its encoder produced?
Plant known rune sequences under explicit rules and retain the exact answer. The alignment controls distinguish prohibited paths, beam pruning, and a high-scoring but incorrect result. Start with the worked alignment diagram if those terms are unfamiliar.
Does the best result account for all the keys tried?
Repeat the complete search on controls and keep its maximum, just as you keep the observed winner. This record preserves nested dictionaries through 256 keys and separates a missing true key from one explicitly included.

A positive control supplies a known answer that the declared method should be able to recover or recognize. A negative control challenges the method with specified wrong keys or a chosen null input. Neither term means that a control represents every possible success or failure. Read the exact inputs and bounds before transferring a result to your own search.

For example, a no-skip decoder passing ordinary-addition controls does not establish that it handles key skipping. Likewise, a score rejecting these shuffled samples does not establish that it will reject the best output from a much larger search. Search space and bounds explains how to keep the claim aligned with the tested procedure.

Choose the input before comparing results

A manuscript page has several representations. Archived runes, corrected runes, decoded rune labels and contextual English are not interchangeable inputs. The image has additional information—placement, color and artwork—that a rune string does not preserve.

  1. Name the source. Record the page ID, file and hash. State whether the input is archived, reviewed or decoded.
  2. State the boundaries. Decide whether headings are included, whether separators are removed, and whether processing crosses words, lines or pages.
  3. Keep the result with the rule. Include the script, command, parameters and output. A number without these details is difficult to compare or reproduce.

For example, the repeat script removes word separators, so a bigram can span two archived words. The prime-sum examples use known decoded runes, while the ordinary page-record sum uses archived runes. The guides explain these differences beside their outputs.

For repeating-period questions, use periodic IoC: it explains column assignment, unequal weights, and why a selected peak needs a matching comparison procedure.

Before using a measurement to rank candidate solutions

Evaluating candidate readings explains the difference between matching a known opening, ranking language-like output and reproducing a full reading. Its worked examples show why an opening test can reject readable text and accept a string whose remainder is meaningless.

Read what cipher operations preserve. A measurement that stays unchanged under every candidate transformation cannot distinguish those candidates. Whole-stream IoC, for example, cannot rank a set of pure transpositions of the same rune stream.

Also distinguish an observed value from evidence that it is unusual. A repeated pair is an observation; claiming it occurs more often than expected requires a stated comparison model. Selecting the best result from many lengths, keys or page subsets is itself part of the procedure and must be accounted for in that comparison. The reproducibility guide explains how to bound a proposed test and report its limitations.

Comparing patterns with chance walks through an exact six-arrangement example, including why the same input can give different probabilities under different selection rules.

Run a first check

Download the reference-data bundle, extract it with its folders intact, and follow the setup walkthrough. These two commands need only Python 3:

python scripts/rune_ioc.py --check
python scripts/rune_ngrams.py lp2-31 --length 2

The first compares the archived rune statistics with the shipped baseline. The second prints a descriptive repeat report for one page. Neither command tries to decrypt an unsolved page or calls the hosted assistant. Image-based checks additionally need the original-image bundle and, for pixel measurements, the documented optional dependencies.
