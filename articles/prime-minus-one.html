The known LP2-56 reading uses a changing shift based on consecutive primes. The shift comes from a separate sequence, not from the identity of the rune being decoded. Following the first few positions makes that distinction concrete.

The transformation

Take prime[j] from 2, 3, 5, 7, 11, … and compute p = (c − (prime[j] − 1)) mod 29. The first shifts are 1, 2, 4, 6, 10, …. This is not the prime value assigned to the ciphertext rune.

At j = 0, index 0 becomes 28; at j = 1, index 0 would become 27. These are arithmetic examples, not assertions about the page’s first two runes.

The historical name φ(prime), or Euler’s totient of a prime, gives exactly these shifts.

Positions start at zero. The first calculation is (25 − (2 − 1)) mod 29 = 24. These four labels begin the literal reading; they are not a four-letter word chosen in isolation. The complete reading supplies the surrounding text and exact output.

Later shifts exceed 28. For example, at rune position 54, the script subtracts 256 from index 21. The result −235 has residue 26 modulo 29, giving Y. Equivalently, reduce 256 to 24 first and calculate (21 − 24) mod 29 = 26. The modular-arithmetic guide explains this wraparound.

What happens at the copied F?

The recorded control copies zero-based rune position 56, an F with index 0, and does not advance the prime sequence there. The surrounding trace is:

The shift after 262 is 268, from the next prime 269. Copying the F leaves that next shift available for rune position 57. Applying a zero shift to F while still consuming the next prime would produce the same F at position 56 but change every later alignment. The output at the interruption alone cannot distinguish the two rules.

Read the prime-stream counter

The CSV columns key_position_before and key_position_after count consumed prime shifts here. At rune positions 55, 56, and 57, they show 55→56, 56→56, and 56→57. The unchanged middle counter confirms that the copied F leaves the next prime unused.

key_slot_before is blank throughout this control. That column describes a repeating Vigenère key; the consecutive-prime stream has no repeating key length to reduce the counter by. Do not interpret a blank slot as slot zero, and do not use the input rune ordinal as the prime-stream position after the interruption.

This interruption position is a parameter of the published reproduction control, recorded through alignment with the archived known reading. It is not inferred automatically by this script and is not a rule to copy every F on an unsolved page. See keystream positions and interruptions.

Four positions in this reading have equal input and output indices, but only one interrupts the key stream. The other three subtract multiples of 29. See the position-by-position audit for the shifts, counters and reproducible counts.

How to replicate LP2-56

Use Python 3 from the repository or extracted reference-data ZIP. No additional package or AI service is needed.

Has this been tried on other pages?

The prime-minus-one reuse experiment tests LP2-00–55 with starting offsets 0–28 and both arithmetic directions, without interruptions. None of its 3190 candidates starts with any of nine declared 12-rune openings. Read the scope before treating this as a negative result: different beginnings and interruption rules were not tested. Complete candidate sequences and reproduction scripts are available with the record.

What if I subtract the primes themselves?

With the same input and key advancement, replacing each prime minus one with the prime lowers every subtraction output by one alphabet position modulo 29. With addition, it raises every output by one. The ordinary-prime variant records that comparison separately and verifies the relation for every candidate. If a search already tries all 29 constant output shifts, these two schedules cover the same outputs; counting both as independent coverage would be misleading.

A separately recorded Fibonacci variant uses the same opening criterion and boundary rules. Its shifts repeat every 14 terms modulo 29: 3190 configurations yield 1540 distinct page outputs. The record explains the repeated-pair check and why larger offsets add no new phases under those rules.
